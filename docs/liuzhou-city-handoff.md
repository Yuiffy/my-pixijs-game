## 可重复的制作流程

1. 先在原始档案查源 ID、完整环、成员和标签，记录实际缺口。不要一开始就用截图手摆楼体，也不要重复下载已归档资料。
2. 在对应 `prepare-liuzhou-*.py` 中生成片区布局，保留源 ID、源哈希和原始几何。来源轮廓与估算体分开，未知楼高、院路、店名及家具明确标为估算。
3. 先裁除车道、建筑、河道、楼梯开口，再三角化铺装；输出面积、并集、净空和朝向检查。以实际输出面核对，不只检查裁切前多边形。
4. 同时更新 `src/components/liuzhou/*-layout.json` 与 `public/games/liuzhou/` 同名副本，重复生成应字节一致。几何、实体、镜头、导航、存档共用布局定义。
5. 做源数据独立核查、真实 Rapier 普通步行往返、浏览器视觉验收；通过后保存依据和未完成项。最后在冻结的生产构建上复核，不能把 HMR 修改前后的截图混作一次最终验收。

现有运行 JSON 已提交，普通启动无需重新生成资料。要改哪个片区就运行对应生成器；只有源数据或依赖变化才按依赖顺序重建上游，避免无意覆盖其他片区。

```powershell
# 示例：城市导入直接读取归档，不依赖在线API。
python scripts/import-liuzhou-city.py
python scripts/prepare-liuzhou-wuxing.py
python scripts/tests/liuzhou-wuxing-west-geometry.py
node --test scripts/tests/liuzhou-wuxing-west.test.mjs
```

生成器依赖按各脚本说明准备：常用 Pillow、Shapely 2.1；山路还使用 NumPy / SciPy。详细重建命令见资料 README。局部封边可用 `prepare-liuzhou-eshan-edges.py`，更新后仍需检查封边与原通道的连接。

## 这次最有价值的经验

| 问题 | 原因与以后采用的做法 |
| --- | --- |
| 两条路投影相交就变成平交 | 桥面、引桥、地面道路分层；仅在真实落地点换层。桥下普通步行必须保持较低 y，车辆和导航也要保留层级。树木避让完整桥梁走廊。 |
| 细化网格后仍然不像真实地形 | 原始 DEM 约30米，10米采样只提高网格密度。统一原点WGS84 `(109.41225,24.31415)`，x东/z南，绝对高程85米对应y=0；保留原 DEM、地面估算和局部山体数据的区别，不凭一个峰顶数字整体拉高山。 |
| 视觉落地而物理悬空，或角色陷地 | 铺装、地形与实体使用同一三角面插值，不能一边平滑采样、一边按另一套网格碰撞。楼体地基沿完整轮廓采样，不能仅看中心高度。 |
| 大商场或跨边界楼体漏掉 | 旧核心边界与扩区筛选各自排除，尺寸上限还会误删大楼。先按源ID核对已有所有权，保留完整环，再统一接管排重；本次12份西侧楼体原本已存在，并非新增发现12栋。 |
| 广场、公园被当空地或填住宅 | 只读way会漏multipolygon；按节点ID拼接完整成员并保留内孔。来源公园、铁路、校园与现有楼栋优先，估算填充避让它们。 |
| 铺装、商场窗带出现闪斑 | 重复道路/共面楼壳会产生重叠面。按源ID和覆盖关系排重；共享窗带用`detailOwnerId`，低楼体绘制用`renderParts`扣去高楼体。保留完整物理轮廓，并核对绘制并集无缺失、无重复覆盖，以及屋顶和地基实际高度。 |
| 地下入口浅蓝缝、穿地或楼梯顶住 | 地形、道路、广场都要开同一个孔；保留门槛以下挡土墙。踏步与开口宽度一致，折返平台留足转身，地面经过地下投影不能被吸下去。窄处镜头可淡出角色，不能靠删除墙体解决遮挡。 |
| 招牌出现无效颜色 | 估算ID是字符串，直接数值运算会产生NaN。用稳定数字后缀作种子，并断言颜色和全部坐标有限。 |
| NPC站机动车道、院墙堵通路 | 以整条人行路线和车道净空核对，不能只看出生点；恢复存档也检查占用。家具和墙体都必须参加通行检查。 |
| 飞行下降触发Ctrl+W关闭页面 | 下降已改C；F飞行，空格升高，Shift加速，Q慢飞。后续新增组合键先核对浏览器快捷键，并验证失焦/暂停后释放输入。 |
| 开车、飞行时身体前后闪动 | 模型回调先读取旧物理状态，相机随后跟随新状态，出现一帧落后。`Scene.tsx`的Frame以优先级-1先推进物理/相机，再更新模型；用实际挂载位置和朝向核对，连续采样至少1秒模拟时间，避免低速起步阶段导致假失败。动作改动还要回归骑手脚踏/握把接触、暂停和近距离镜头。 |
| 鼠标突然拉扯、速度过高 | 捕获输入拒绝非有限值或单轴超过256像素的异常采样，不积累补偿；这是保护阈值，不能证明每台设备的原生根因。`controls.ts`处理原始输入回退和Alt/暂停，`lookSettings.ts`保存20%—200%灵敏度，默认60%；正常分段快速转向不应被限成慢速。 |
| 首次进入一直等整城加载 | Worker按256米分区生成道路/远景，完整碰撞和当前位置附近场景就绪即可进入。每500ms按角色位置调整优先级，远处继续加载，完成前进度最高99%；卸载需终止Worker并释放几何。不能为加快进入跳过碰撞。 |

当前五星街数据：23份来源楼体、6份估算低矮商铺、98段立面、49处家具；两条西侧来源衍生步行路线、六条店前连接。完整源轮廓仍用于碰撞和存档，裁切只作用于重叠楼壳的绘制。重复生成的布局 SHA-256 为 `6D312C736CED53B2AAD243E51AE439C036E5BCB2E8A7D867F79C59E8B4A9BF4A`。

## 验证与发布习惯

源码修改先跑 changed-files ESLint；提交前按仓库要求顺序执行：

```powershell
pnpm exec eslint src/components/liuzhou/<改动文件>
pnpm run check
pnpm run build
```

保留 Next 构建的 ESLint，不让 tsc 与 next build 并行。独立 `.cjs` 测试脚本不在TS项目内时，使用适合脚本的 ESLint 配置，不要因此绕过游戏源码门禁。

浏览器先确认目标URL响应，再用已安装Chrome。所有一次性测试上下文先调用 `scripts/lib/liuzhou-test-browser.cjs` 的 `quietContext`，启动参数带 `--mute-audio --disable-speech-api`，保留游戏本身正常声音与Pointer Lock。禁止测试移动用户系统鼠标或播放TTS。

按改动选用 `scripts/verify-liuzhou-*.cjs`，通过 `LIUZHOU_BASE_URL` 和 `LIUZHOU_QA_DIR` 指定服务和报告目录。普通通行用真实移动逐段往返，不能用传送到终点代替。每张证据图都打开检查，结合 PNG sanity、`window.render_game_to_text()`、DOM/画布尺寸和console/page errors；全黑图先判断捕获路径。最终眺望图等待 `loading.complete`，渐进加载测试则明确在未完成时进入并行走。

# 游戏大厅：发现与回访

本轮来自持续目标：检查项目缺陷、优化现有游戏并探索新玩法。先解决 22 款作品的共用入口：大厅过去只有分类长列表，自走棋只出现在主视觉中，新游戏的浏览统计还依赖另一份过期名单。

## 设计与行为

沿用现有深色展厅、大幅主视觉和薄分隔线列表，以薄荷绿标记当前选择。内容顺序是精选游戏、搜索与个人游戏库、游戏目录、网页实验。保留原有首屏入场和滚动显现；收藏按钮采用短促颜色反馈，遵守减少动态效果设置。

- 搜索名称、描述、玩法与分类；多个词取交集，兼容大小写与全半角。可叠加类型、收藏和最近打开条件。
- 默认保留分类顺序；最近更新、最新推出在全部结果中统一排序。没有更新日期时以推出日期排序，界面仍显示“更新未记录”，不编造更新日期。
- 收藏按钮与进入游戏的链接分开，支持键盘、触控、跨标签页同步。收藏只保存在当前浏览器，没有云同步。
- 最近打开最多保留 12 款，本站游戏由根布局监听实际路径进入；不因悬停预加载或修改游戏查询参数产生记录。独立托管的 Knight 在大厅链接被激活时记录，直接访问其独立页面无法由本站布局追踪。
- 清空打开记录保留收藏和游戏存档。禁用浏览器存储时界面保持可用，并说明收藏仅在本次页面中保留。
- `q`、`category`、`shelf`、`sort` 保存在网址中，刷新、分享链接与浏览器返回可恢复筛选；收藏/历史内容仍属于各自浏览器。每次输入替换当前历史项，不制造逐字返回步骤。
- 大厅筛选变化不再重复上报页面访问。浏览数接口从同一目录读取全部本站游戏，修复 RESET、平陆运河、黄金微针、沙滩排球漏统计。

## 文件与维护

- `src/components/gameLibrary/catalog.ts`：大厅与访问统计共用的游戏目录。日期证据继续维护在 `docs/demos-dates.md`。
- `discovery.ts`：纯搜索、筛选、排序与网址处理。
- `storage.ts`：独立的 `sui-game-library-v1` 存储键；过滤损坏数据、重复项和非法链接，不触碰游戏存档。
- `RecentGameTracker.tsx`：站内页面进入记录，不引入游戏引擎或大型目录到根布局。

新增游戏时同时补目录和真实图片。目录测试会检查所有 `/game/*/page.tsx` 路由都有且只有一个入口，并核对图片文件和日期。修改大厅本身不改变任何游戏的更新时间。

## 验收入口

```powershell
pnpm library:test
$env:LIBRARY_URL = 'http://localhost:3955/demos'
pnpm library:verify
pnpm run check
pnpm run build
```

浏览器脚本先请求目标 URL，使用安装版 Chrome、`--mute-audio`、禁用语音；检查截图色彩有效性并保存 DOM 结果列表。输出默认在 `tmp/game-library-qa/`，可由 `LIBRARY_OUTPUT` 设置生产版证据目录。脚本覆盖搜索交集、收藏不误跳转、刷新与跨标签同步、真实进入维阿发掘局并返回、清空历史、网址恢复、排序、390/320px、键盘焦点和禁用存储后的真实触控操作。Knight 仅验证跨站入口记录，目的页使用测试桩，不能据此声称独立游戏功能已验收。

生产验收将广告与百度统计外部脚本替换为空响应，避免它们的长连接影响页面就绪判断；本站浏览数接口和访问上报仍实际执行。此验收不覆盖广告与第三方统计本身。

测试结果与生产构建状态见 `progress.md` 最新记录。

## 后续可继续优化

大厅现在解决了发现与回访。后续应进入具体游戏做完整体验审查，优先检查手机操作、首次游玩引导、失败后重开和存档恢复，再根据实测选择玩法扩展；不要仅凭路由可打开就认定游戏体验完整。

## 1. 制作人结论

做一款以跳跃为核心、带轻战斗与探索成长的横版动作冒险：岁己经营小餐馆的第一天，要穿过春日小镇，把第一批外卖送到居民手里。玩家从绕着障碍走的新手，成长为能挑起敌人、踩踏借力、穿过屋顶的熟练配送员。

玩家应当记住的画面：**岁己用托盘挑起扑来的面团怪，跳起来踩它借力，越过遮雨棚，落到阁楼窗台，把热饭递给等在那里的人。**

“送外卖”提供出发的理由、可操作的环境和交付的回报；“跑跳与借力”承担每几秒钟的核心乐趣。主线可慢慢观察、失败重试；通关后，玩家自愿挑战一气呵成的热气配送。

目标体验比例可暂按动作约六成、探索约三成、交流与整备约一成讨论。目标是紧凑的完整小品，暂按四个街区、十二个主关卡单元、首次主线约两至三小时设计；这些是范围估计，最终时长取决于实测，不能靠拉长路程凑数。

## 2. 当前版本为什么显得像 demo

本轮检查了 `content.ts`、`engine.ts`、`SpringScene.ts`、`SpringGame.tsx`、`docs/sui-spring.md`，以及既有发布验证中的开场、第二关中段、第四关中段截图。截图已经打开目检，属于历史产物；本轮没有重新试玩，以下判断来自代码和这些画面，不冒充本轮真人操作感受。

| 当前证据 | 对体验的判断 | 新方向的处理 |
| --- | --- | --- |
| 四关主要都是同一高度地面分段，加上几组悬空平台；变化集中在机关和敌人清单 | 玩家容易把后续关卡读成同一种地图加障碍 | 每关先确定空间事件，再设计落脚点：穿过厨房、爬上餐车、进入阁楼、跨过雨棚 |
| 金币用于计数和纪录；每关三颗星主要摆在高路上 | 主动冒险缺少有分量的回报，奖励形式容易被预测 | 给支路装备、独特场景、居民后续、可操作捷径；普通碎币只引导动作 |
| 输入只有左右、跳跃和加速，主要战斗依赖踩头和踢壳 | 主动处理局面的手段少，避开威胁常常比与之互动更直接 | 增加托盘挑击，让敌人同时成为危险和可利用的跳跃资源 |
| 各关故事主要是开头、结尾文字；到达横向终点完成关卡 | 行动过程与故事变化联系弱 | 交付要发生在场景内，并带来可见变化和后续关系 |
| 最终敌人沿用投弹行为，加三次踩头与封闭区域 | 终点缺少对本章空间机制的总结 | Boss 改变落脚点、攻击路线与可反击机会；用所学动作拆解战场 |
| 主角使用待机、跑姿两张图；敌人主要依靠单图缩放，背景大量重复山丘、村屋、树形 | 动作状态和地点个性表现不足 | 优先制作动作状态与真正能行走的建筑，再完善装饰 |

已有可变跳高、惯性、宽限、输入缓存、快速重试、独立模拟与存档值得保留。它们是进一步设计的基础。是否有趣仍需要观察玩家会不会主动探索、尝试第二种解法、愿意再跑一次。

参考用户点名作品时，把它们当作本作想达到的体验要求：基础动作值得反复玩；机关有意料之外的巧思；攻击和成长能改变选择；地方与人物值得记住。这里不代言任何制作人，也不声称复现某位制作人的个人方法。

本作与《风邮小镇》的分工必须清楚：后者已经围绕地标、地图、方位记忆与返程设计。本作让目的地及眼前路线容易理解，把难点放在起跳时机、落点、速度和动作组合。主线采用清楚的关卡连接，不增加地址检索、迷宫式路网或反复原路跑回餐馆。

第一版也不加入经营排班、接单抢单、饥饿值、随机装备词条、体力条、每日任务或刷钱升级。餐馆承担休息、人物关系和装备选择；动作关卡承担主要游戏时间。

## 4. 招牌玩法：把危险变成落点

基本动作是移动、长短跳、加速、托盘挑击。踩踏与按住跳跃获得更高反弹从一开始就存在，不把完整基础手感锁在升级后。

托盘挑击是朝面向方向的一次短距离上挑，可在地面或空中使用，不用鼠标瞄准。它有清楚的动作起手、命中和收招，不能通过连按形成永远安全的攻击墙。具体判定和时间窗口在原型中调整。

第一类招牌敌人是圆形的“面团团”：

1. 正常时会向玩家蹦来，必须观察与处理。
2. 正面挑中后，它短暂向上抛起，变成可踩的借力目标；弹性轮廓与动画清楚区别于普通受伤状态。
3. 玩家可以从下方走过去，也可以跳上去踩踏，获得高反弹，够到原本够不到的雨棚。
4. 再次攻击可以清除它，选择安全清路就暂时放弃这个落点。
5. 一次借力后它退场，不能在同一只身上无限升高。关键主路必须有恢复机制；误杀不会导致软锁。

这形成真正的判断：“现在消灭它，还是先留给下一次跳跃？”之后把同一个规则放进移动台、低天花板、侧面来敌、连续高路，变化来自空间与时机。

技能应有不同风险的用法：地面挑击容易，跃起途中挑击更灵活；普通路线可以逐个处理，高手路线可以在连续移动中组合。新手不必完成空中连段才能看见结局。

托盘与机关的交互也保持可读：带有统一弹性边缘的翻板可以被挑起，普通墙壁不会突然变成跳板。交互物需要轮廓、材质、动画共同提示，不能只靠一种颜色。食物主题不能成为“什么都可以弹”的任意解释。

## 5. 战斗、装备与成长

战斗要让玩家争取位置、打开路线和掌握时机。敌人数量控制在能看懂关系的范围；基本敌人以一至两次有效处理结束，不靠血量拉长遭遇。

| 敌人职能 | 玩家判断 | 与跳跃的联系 |
| --- | --- | --- |
| 面团团：扑近后可挑起 | 清掉还是留作借力点 | 高路、连续踩踏、动态落点 |
| 硬壳保温罐：正面有护板 | 绕后、踩头或等开盖 | 要求改变高度与攻击方向 |
| 发条餐车：沿轨道来回移动 | 等待、搭乘还是破坏 | 速度匹配与移动平台落地 |
| 吐籽花：提前鼓起再发射 | 跳过弹丸、借遮挡接近或后期反弹 | 长短跳、射线与落点选择 |
| 抢食小鸟：沿预告路线掠过 | 留在安全区还是借它跨越空隙 | 观察周期与空中修正 |

现有虚拟角色优先担任店主、顾客、同行与友好挑战者，保留形象辨识度。一般战斗对象用食物精灵、野生小动物与失控发条设备，不继续把熟悉角色仅作为可被踩掉的怪物皮肤。

建议采用少量明确的成长节点：

- **开场：基础托盘。** 可以攻击、挑起指定目标；它就必须足够好玩。
- **第一街区结束：隔热包边。** 托盘获得反弹带明确标记的热弹能力，增加攻击与开机关的方法；反弹是一种时机选择，不能常驻举盾无敌。
- **第二街区结束：蒸汽餐箱。** 解锁一次短促的空中横向冲刺，每次可靠落地后恢复。它改变后半程路线设计；不无限悬空，不在未获得前安排必需它的主路。是否保留这个能力，以基础跳跃与挑击试玩结果决定。
- **支路奖励：少量装备改装。** 例如加宽托盘判定但延长收招，或缩小判定换取更快恢复；在整备点选择，带来不同打法。先验证两种就足够，不扩成装备海。

主线能力通过推进必得，不能用高难支路的奖励反过来要求新手。基础跑速、跳高不做逐级加点，避免玩家熟悉的落点关系不停变化。金币可兑换餐馆装饰或已解锁改装；一次性发现与订单报酬承担主要收入，不要求刷重复敌人。

## 6. 每关要是一件值得记住的事

每关先写下“玩家会讲给别人听的那件事”，再画地图。每个主要玩法至少经过安全示范、独立尝试、变化组合、一次高潮；不是四块固定模板的机械拼接。

关卡包含清楚的主路、可见的高路诱惑与少量隐藏空间。主路保留必要的观察和动作挑战；新手可停下来逐段过。高路强调连续动作与风险收益。隐藏空间用声音、露出的物件、可见建筑关系提示，避免逐墙乱撞。

首次游玩约八至十二分钟，实际时长待测。

| 段落 | 具体事件 | 玩家在不知不觉中学到什么 |
| --- | --- | --- |
| 餐馆门口 | 顾客在街对面阁楼挥手；出餐台滑出包装好的热汤。玩家立即能走动 | 知道送给谁、为什么出发，目的地通过画面成立 |

## 7. 完整篇章草案

四个街区各三个主关卡单元。第三单元可把 Boss 或追逐整合进关卡，不另用大量走廊填充。每一区都有独立的形状、材质、动作主题与居民关系。

| 街区 | 三个关卡事件 | 核心动作与场面 | 完成后看得见的变化 |
| --- | --- | --- | --- |
| 春芽街：早餐时分 | 阁楼热汤；面包房后门；失控的烘炉蟹 | 长短跳、挑击借力、烤盘升降；用烘炉排气登上背部关闭阀门 | 小餐馆有了第一张合照，花匠把门口花盆送来 |
| 集市：午餐高峰 | 穿行流动摊位；搭上运货餐车；百手分餐机 | 移动落点、低顶短跳、反弹弹丸启动分流开关；传送带逐步改变战场 | 摊主共同铺好穿街捷径，熟悉的顾客开始替店铺招呼生意 |
| 雨檐区：阵雨来临 | 屋檐接力；温室里的晚餐；抢食鸟追逐 | 看懂遮挡后的落点、先预告再变化的雨棚、有限空中冲刺；追逐有安全段和就近重试 | 收起的雨棚重新展开，温室与街角连起来，居民送出餐会食材 |
| 山坡剧场：开饭之前 | 布景吊台；最后一桌订单；失控宴席机 | 组合此前能力；登上运动中的大设备，把三个部件依次停稳，完成最后交付 | 夜色中各家灯亮起，送过餐的人来到长桌，为岁己留好位置 |

总体故事：小餐馆试营业的第一天，与小镇晚间的春日餐会相遇。居民有各自正在做的事和小矛盾，送餐过程中逐渐认识他们。结尾的情感回报是忙了一天的人也能坐下来吃饭。保持原创童话，不包装成真实人物经历。

主线短对话发生在安全区，不在跳跃中弹窗截断操作。可选支线让一位顾客从“订单编号”变成记得住的人，例如总说不饿的修理师，把自己那份面包留给了屋檐下的小动物；再次经过时能看见行为，而不是只读解释。错过支线仍有完整结局。

## 8. Boss 和恶作剧的标准

Boss 要让人记得一场动作过程。烘炉蟹的初版可以这样设计：

1. 正面夹击迫使玩家越过低矮钳子，背部暂时不可站立。
2. 炉体鼓起、阀门发亮，随后排气抬起旁边烤盘；落脚路线先能看见。
3. 玩家跳上烤盘，再踩借力目标登背，挑开阀门，造成一次有效破坏。
4. 下个阶段蟹转身，烤盘位置变化，原来的解法需要调整起跳方向；不能只是重复三遍相同等待。
5. 关闭后它恢复成居民使用的小烤炉，胜利改变场景并打开出口。

主线 Boss 先以掌握一个局面为目标，避免长时间无敌等待或高血量磨损。重试点放在门口；已看过的开场可略过。

恶作剧采用“先有迹象，第一次允许安全吃惊，之后能利用”的约束。松动棚布会抖、怪花会吸气、餐车会先响铃。反常事件应让玩家学到稳定规则。可选的恶作剧挑战房允许更狠的预期反转，但入口提前表明挑战性质并就近重试。主线不使用无预警即死、假检查点或假存档。

## 9. 配送压力、失败与技巧成长

主线普通订单不倒计时，不因停下来观察而食物变冷、奖励缩水或出现差评。包装正常保护食物；受击影响角色生命，不另加一个需要时刻照顾的汤汁平衡条。

热气配送作为已通关关卡的可选挑战：入口明确计时，暂停停止计时，超时仍可完成；奖励纪念章与外观，不锁主线能力或剧情。某些特殊餐品可用于专属挑战，例如不能连续落地重砸的蛋糕，但必须自愿选择且不成为主线负担。

检查点按动作段落设置，初步目标让常见失败只重做约十五至三十秒的有意义片段，最终按真人表现调整。死亡尽快恢复控制；保留已获得的关键升级、支线发现和已经开启的捷径，重置当前片段战斗，杜绝重复领取永久报酬。可随时退出，在最近检查点继续。

技巧成长主要来自路线：短跳躲低顶、助跑过远隙、空中修正落点、移动台相对速度、踩踏借力、攻击和起跳衔接。关卡回顾只在玩家需要时指出具体进步，例如“这次连续通过三个雨棚”，不在第一次通关时贴满低分、死亡数和评级。

辅助模式可以增加容错窗口、受伤保护或慢速练习；必须公开标明设置，保持动作因果清楚。提供单段练习和快速重试。是否有现实中的训练迁移不作承诺；本作先证明玩家能把学会的动作应用到未玩过的关卡。

## 10. 美术、声音与镜头

视觉方向是有实际空间结构的春日小镇：可进入的面包房、可以攀登的雨棚、跨越街道的餐车、能从窗外抵达的阁楼。白发、红帽、红披风保留，增加明确的配送餐箱和托盘动作；细节服从小尺寸辨识。

四区分别用早餐光、集市遮棚、雨水玻璃、暮色灯火形成区别。碰撞边缘与装饰的明度、轮廓要分开；食物弹性目标和坚硬目标有不同材质。不能只更换背景色后继续摆同一种浮空木板。

主角至少要有待机、起跑、稳定跑动、刹停、起跳、上升、下落、落地、挑击、受伤及交付状态。先完成开场会实际用到的动画，不批量生成全套未验证资产。敌人必须表现预备动作、可利用状态和恢复状态。道具和角色按同一比例、光向和描边验收。

镜头根据速度前视；进入高路适度抬高，并在关键起跳前交代落点。Boss 场景可以拉开构图，但不能缩小到看不清角色。震动与停顿克制，可关闭。玩家在正常显示尺寸和触屏横屏上都应看清攻击预兆。

声音承担信息：餐车铃说明开始移动、棚布绷紧说明将反弹、锅炉排气说明窗口开放。送达有碗碟轻响和居民的简短反应；减少纯装饰提示音。所有重要声音都有视觉对应。HUD 保留生命、当前工具和简单目的，热气模式才出现计时；订单介绍放安全位置。

## 11. 执行顺序与否决条件

现在只讨论方向。确认之后按以下顺序执行，每一步都服务于完整作品：

1. **先验证招牌动作。** 用一个灰盒房间做托盘挑击、面团团抛起、踩踏借力、地面路线和高路。确认玩家能看懂因果，且比只踩头多一个值得做的选择。
2. **做一段完整代表体验。** 完成“阁楼那碗热汤”，包含开场拿餐、动作学习、支路奖励、一次有铺垫的惊喜、小高潮、场景内送达、捷径和第二单邀请。配上主角必要动画与一套完整环境。它必须体现最终质量，不能仅把灰盒加长。
3. **验证成长与场景变化。** 做第一场 Boss 及隔热托盘，再用第二街区证明反弹能力会创造新问题；之后才决定蒸汽冲刺是否值得加入。
4. **扩展完整四区。** 每区逐关验证主题、空间与节奏，补齐关系变化、结局、存档、触控、辅助和可选重玩内容。

代表关卡是对方向的检验，不是完整游戏的替代交付。目标始终是有开头、成长、高潮、结局和可选精进的完整冒险。

建议邀请五至八名不同横版经验的玩家试玩；这是定性测试计划，不是已取得的数据或统计证明。观察：

- 玩家能否在开场约一分钟内说清楚送给谁，以及眼前可以做什么。
- 经安全示范后，能否自己发现至少一次“挑起再踩”的用法；若多数人仍需旁边口头解释，应先改反馈与布局。
- 高路是否让人主动尝试；若玩家只是为清空收集数字折返，支路的诱惑仍不够。
- 死亡后能否说出下一次准备改变的动作；若反复把失败归因于看不清、判定不明、镜头迟到，先修正这些问题。
- 送达后，玩家能否记得顾客或场景变化，并愿意接下一单。
- 通关后是否有人自发想更流畅地再跑一次；零人愿意时，不以自动通关或完成率为趣味性背书。

若挑击借力不好玩，先改变目标运动轨迹、命中反馈、落点组合及节奏；不要靠多加装备掩盖。若配送仍像“换成餐盒的送信”，必须检查餐车、厨房、挑击与顾客交付是否实际改变了玩法。若计时破坏初学者观察，主线保持无计时，挑战模式单独调节。

## 12. 与当前工程的衔接

沿用 Next.js 页面、Phaser 渲染与独立固定步长 TypeScript 模拟；这次方向不需要换引擎。保留现有输入容错、暂停与失焦清理、快速恢复和调试文本接口。

需要重新组织的是关卡结构、角色战斗状态、装备与永久世界变化、场景内交付、纵向镜头和动画。模拟拥有战斗、任务及存档事实；Phaser 负责画面；DOM 负责菜单、整备与设置。新状态分模块管理，不把全部逻辑继续堆到单一场景中。

美术执行时先审核角色原图和现有资产，制作单关所需的动作表、尺寸表与环境清单。采用可追溯生成或绘制流程，统一后再制作图集；不把临时概念图直接当作具有正确碰撞与动作状态的游戏精灵。

新版存档必须版本化。保留旧四关通关纪录作为历史，不能将它们误认成新关卡完成；不删除用户旧档。旧原型路线可保留作归档，正式标题与导航在实现时统一更新。

后续规则测试应覆盖挑击转态与借力、误杀后的可恢复性、冲刺次数、移动平台、检查点永久与临时状态、奖励幂等及存档迁移。原有自动通关规划器需要随动作和地图更新，不能拿旧四关通过证明新版完成。

浏览器测试使用安装版 Chrome、静音和 speech stub，先确认服务响应；全页截图做颜色与透明度检查，并逐张打开，交叉检查文本状态、DOM、画布尺寸和控制台。真人试玩与视觉验收独立于自动可达性测试。源文件编辑时定向 ESLint；提交源码前按仓库要求顺序执行 `pnpm run check`、`pnpm run build`，保留 Next 构建 ESLint。

本文末尾保留原方向的执行约束；后续实现记录与验收以 `sui-delivery-progress.md` 为准。

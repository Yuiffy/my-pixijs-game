# 武侠小说生成器 v6 设计说明

## 1. 产品目标

这不是随机段落日志，也不是把预写主线换一批人名。当前目标是一个可持续游玩的武侠生涯生成器：世界先保存地点、人物行程、关系、武学和机会，玩家再主动选择眼下想做的事，系统最后把已经发生的事实写成小说。

玩家应当能明确回答三个问题：

1. 我现在想走哪条路？
2. 我今天为什么去这个地方、见这个人或练这一招？
3. 这一幕之后，世界中有什么真实状态发生了变化？

旧版的问题正相反：事件自动滚动、人物为剧情瞬移、选择语义神秘、关系只剩好感、武学只有名字、战斗只做一次属性判断、结果埋回上文小字，并且十二回无条件结束。v6 以玩家主动生涯循环替代了这些约束。

## 2. 同类作品调研与取舍

调研关注可迁移的系统原则，不照搬内容量或界面。

| 作品 | 可迁移原则 | v6 的落点 |
| --- | --- | --- |
| [太吾绘卷](https://store.steampowered.com/app/838350/) | 随机世界、持续生活的 NPC、门派绝艺、距离与见招拆招 | 持久人物、地理路网、武学传承、招式距离和克制 |
| [鬼谷八荒](https://store.steampowered.com/app/1468810/) | 亲族朋友和独立人生轨迹，拜师、传授、宗门与奇遇交织 | 复杂关系边、人物目标、限时机会、传艺和创派 |
| [了不起的修仙模拟器](https://store.steampowered.com/app/955900/) | 世界模拟先产生事实，玩家干预后形成传奇 | 世界模拟、事件导演、小说转写三层分离 |
| [大侠立志传](https://store.steampowered.com/app/1948980/) | 多身份、多武学和江湖生存形成不同路线 | 三种出身、出身专属路线、秘籍来源和人物追寻 |
| [漫野奇谭](https://store.steampowered.com/app/763890/) | 事件按背景和关系定制，结果长期改写人物 | 场景手稿、人物关系、势力和伏笔持续写回 |
| [博德之门 3](https://store.steampowered.com/app/1086940/) | 玩家目标、同伴立场、关系和局部选择共同推动长程叙事 | 不设唯一主案；人物意图、可暂停线索和章末续行共同决定故事 |

由此确定六条约束：

- 世界状态先于文本，人物不能只为当前场景出现。
- 戏剧化只改变合理候选的权重，不能取消位置、脚程和期限。
- 玩家要能主动追人、赴会、练功、查秘籍或休息，不能只等随机相遇。
- 人物关系、招式来源和势力后果必须跨章节保存。
- 小说正文不直接抄概率、掷签、点数、秒数或战斗日志。
- 扩展内容必须进入同一套状态和验证协议，不能另建一条硬编码主线。

## 3. v6 主循环

```text
独立随机姓名与世界种子
        ↓
按出身选择眼下路线
        ↓
从真实可达活动中安排行程
        ↓
世界按脚程推进，人物同时移动
        ↓
生成一幕有地点、人物和因果的场景
        ↓
玩家选择，执行普通判定或逐招战斗
        ↓
独立结算新正文与长期后果
        ↓
三幕合成一章
        ↓
开启下一章并继续，或由玩家主动暂结此卷
```

章节是阅读节奏，不是寿命上限。第 12 幕之后仍可进入第五章、第六章和更远章节；限时盛事会照日期结束，人物、关系、秘籍和未完成线索继续存在。

姓名随机与世界种子完全解耦。姓名按钮每次使用独立随机熵并排除当前姓名；修改姓名不会改变人物阵容，重抽世界种子也不会改写已经选好的姓名。

## 4. 玩家主动路线

每种出身至少提供三条初始路线，路线只调整活动优先级和眼下目标，不锁死后续内容。

| 出身 | 路线示例 | 主要活动 |
| --- | --- | --- |
| 门派弟子 | 守山修艺 | 练本门招式、请同门指点、实战拆招、自创武学 |
| 门派弟子 | 同门相知 | 与大师姐、小师妹同练、分担差事、结交或倾心 |
| 门派弟子 | 请剑下山 | 主动选地点、追人物、赶大会和寻奇遇 |
| 无门游侠 | 百家问招 | 找使招之人、追秘籍、旁学并融汇新招 |
| 无门游侠 | 结伴人间 | 追寻听说过的人，发展结交、倾心、讨教或恩怨 |
| 无门游侠 | 逐浪寻奇 | 追限时奇遇、武会与地方传闻 |
| 镖局护卫 | 守诺行镖 / 广结同路 / 卸旗远游 | 护送查路、人情往来或自选下一程 |

路线可以在后续规划中更换。`PlayerAgenda` 保存当前路线、进度、目标线索、目标人物和人物意图；它不是一条预写任务链。

## 5. 行程、线索与限时机会

`generatePlayerActivities` 每次从当前事实生成可执行活动：

- 练习最生疏的本门招式；
- 拜访同地人物，或沿真实道路追到对方当前所在地；
- 将人物意图设为结交、倾心、复仇、讨教或留意；
- 主动追查有明确来路和落点的秘籍抄本；
- 提前赶往或正式参加比武招亲、天下论武会、秘境和势力合练；
- 去相邻地点调查、休息、推演自创招式、传艺或开宗立派；
- 暂不追目标，让事件导演从当地事实中选择一幕。

活动公开地点、脚程、期限、风险和定性后果。选择卡不显示精确成功概率；内部仍保存确定性判定数据，以保证同种子、同选择可重放。

`CampaignLead` 可暂停、恢复、推进、完成或过期。人物线索会跟随人物移动；秘籍线索会跟随抄本状态；盛事线索会随日期开放或错过。修复后的结算只在存在相同 `opportunityId` 时走盛事分支，不再把所有无 ID 的人物和秘籍线索误判为盛事。

提前赴会与正式参会是两种不同状态。提前到场只能查规矩、结识早到者或帮忙准备；到开场日正式参加后才记为 `attended` 并结清对应线索。

## 6. 地理与人物模拟

默认江湖有 12 个地点和 22 条双向道路，包括玩家山门、洛阳城、百艺会馆、北斗桥、听雨渡、旧宅、诊棚、白露村、黑风岭，以及幻真楼、星游别院和四禧庄。

每个 `WorldLocation` 保存区域、类型、地图坐标、危险、标签和连接。`findWorldPath` 使用图搜索，`worldDistance` 以真实路段计算脚程。主角和人物每天最多走一段相邻道路；抵达后按事件、目标或日常路线停留。

每个 `WorldActor` 保存：

- 当前地点、住所、目的地、路线和停留截止日；
- 角色职责、性格、阵营和带优先级的个人目标；
- 近期记忆；
- 已会招式、熟练度、习得来源和见证者。

戏剧调度可以让有旧识、共同目标、秘密或恩怨的人更容易再次相遇，但不会把他们传送到现场。`render_game_to_text()` 会公开人物坐标、移动记录、导演候选理由和实际到场者，便于验证画面与状态一致。

## 7. 人物原型与复杂关系

`wuxiaRoster.ts` 从项目自走棋角色池复用头像、技能和公开关系梗，再做武侠化适配：

| 原型组织 | 武侠化势力 |
| --- | --- |
| VirtuaReal | 幻真楼 |
| PSPLive | 星游社 / 星游别院 |
| 四禧丸子 | 四禧庄 |
| 独立角色 | 散游盟 |

每个种子稳定抽取八名活跃人物，并保证四方均有代表。核心生涯包还可按出身加入大师姐燕栖梧、小师妹江小满等生活圈人物。随机生成的秘密只属于游戏世界，不被描述为现实人物事实。

关系不是一个通用好感值。世界支持亲子、养亲、手足、舅甥、师徒、同门、结义、友人、情爱、对手、宿敌、仇敌、欠命、护持和同行等有方向的边。同一对人物可以同时是同门、旧友和竞争者。关系的信任、情意、亏欠、积怨和忠诚会影响相遇权重、同行、背离、势力态度和后续正文。

倾心不会一次选择就直接变成爱情。玩家先表达意图，关系按已有信任和后续共同经历继续成长；被拒绝也不会把人物从世界删除。

## 8. 多原型事件导演

自由活动仍需要导演，但导演只能从世界事实中选材：

- 人物目标生成追踪、保护、挑战和联络；
- 两名有关联的人同场可生成恩仇、欠情、师承和亲友事件；
- 地点可生成市井假令、荒路踪迹、诊棚求药和门派争议；
- 上一幕选择会产生传闻余波；
- 藏匿秘籍和伤势会形成独立候选。

最近出现过的原型和人物会降权；连续人物场景后，地点或余波会升权。首次秘籍、正式约战和余波有逐步增加的兜底压力，保证系统可见但不固定在某一回。

运行时新场景只使用 `sandbox-*` 或 `campaign-*`。旧“沉星渡/归潮阁”事件构建器仍留在迁移代码中，但 v6 新建、加载和导演路径均禁止进入它们。

## 9. 武学、秘籍与成长

`WorldMartialArt` 描述门派、品级、内外功、兵器、源流、要旨、禁忌和所属招式。`MartialTechniqueDef` 保存攻、守、身、控、破、医等性质，以及威力、迅捷、命中、距离、耗气、冷却、难度、标签和克制。

人物通过 `ActorTechnique` 保存个人熟练和来源：家传、师授、秘籍、观摩、偷学或自创。练功会改善具体招式；观摩和偷学保留原主；每局三册角色抄本有真实地点、来路、持有人和藏匿、携带、售出、归还状态。

秘籍不再只靠随机导演发现。v6 会把抄本传闻写成可主动追查的 `manual` 线索，玩家可在行程页沿道路去找。带走并修习后线索结清；只追来路或封回原处时，线索仍可继续。

## 10. 确定性逐招战斗与势力后果

战斗复用自走棋的确定性随机源和“状态先演算、表现后消费”原则，不直接把 Phaser 实时对象写进小说存档。每场战斗保存双方距离、内息、招式冷却、命中、闪避、格挡、破招、状态、伤势和胜负。

小说只选取关键攻防转写，按 `actorId + techniqueId + result` 去重。完整交换记录只保存在可序列化状态中，供确定性重放、自动验收和开发调试；玩家界面的“交手实录”只呈现招式往来、定性伤势与内息变化，不显示气力分数、伤害点数、冷却或内部标识。

异派交手后，系统从对方起手、收势和实际使用招式识别武学来源，写入 `FactionKnowledge`：

- 认出的具体招式；
- 证据和辨认把握；
- 对手、场合与胜负；
- 切磋、公开比试或敌对冲突；
- 对该势力往来和戒心的真实变化。

敌对冲突不会因为玩家获胜而错误增加对方好感。

## 11. 自创、传艺与创派

练功、实战和辨招会积累武学领悟。达到内容包规则要求后，玩家可以选择守势、破势或行路身法为核心，结合已掌握招式生成自己的武学。自创招式会同时写入世界招式定义、主角习得记录、叙事武学谱和传承状态。

有自创招式后可以先开一日传艺馆。学徒必须是已经真实相识、仍在江湖且尚未入册的人物；系统保存 `followerActorIds`，刷新和续章不会把追随者退化成一个数量。

名望、追随者和自创武学达到规则要求后可正式开山。新门派会：

- 获得稳定 ID、自然名称、门规和驻地；
- 改写主角门派身份与称号；
- 进入势力志；
- 接管自创武学的传承归属；
- 在后续人物和势力回应中继续存在。

创派命名会先清理地点中的“门驻地/驻地/山/城”等地理后缀，避免出现“青云门驻地行止门”。

## 12. 小说转写与结果呈现

`chooseNovelAction` 的顺序固定为：

1. 执行内部判定或战斗；
2. 应用主角资源效果；
3. 写回世界位置、关系、秘籍和招式；
4. 推进人物、势力、线索与生涯传承；
5. `composeScene` 生成场景手稿；
6. 保存 `pendingOutcome` 并停留在独立结算；
7. 玩家点击继续后才回到规划或进入章末。

选择区以低、中、高风险和“把握颇高、尚有把握、胜负未定、颇为冒险、机会渺茫”说明形势，不显示精确概率。结算显示“应手/失手、此事已成/横生波折”，不显示掷签数字或“检定成功”。小说正文禁止出现规则概率、秒数、点数、“本局开始”或技能面板说明。

每个 `SceneManuscript` 保存地点、出场人物、势力、招式、选择、结果、后果和正文。章末小结引用本章实际人物、盛事、武学领悟、自创招式和门派；未完成线索继续进入下一章。

## 13. v6 状态与存档

`NovelState.version` 为 `6`，本地存档键为 `wuxia-novel-save-v6`。`campaign.version` 当前为 `1`，`world.version` 当前为 `2`。完整状态必须可 `JSON.stringify`，不保存函数、React 引用、DOM 或 Phaser 对象。

| 层 | 关键数据 | 责任 |
| --- | --- | --- |
| 游戏层 | `turn`, `chapter`, `hero`, `pendingOutcome` | 当前幕、章节、主角与独立结算 |
| 世界层 | `locations`, `actors`, `relations`, `manuals`, `movements` | 地理、人物、关系和物件事实 |
| 生涯层 | `agenda`, `leads`, `opportunities`, `factionKnowledge`, `legacy` | 玩家目标、期限、辨招、自创、传艺和创派 |
| 武学层 | `martialArts`, `techniques`, `ActorTechnique` | 招式定义、门派归属、来源与熟练 |
| 战斗层 | `WuxiaCombatResult` | 可重放的逐招交换和胜负 |
| 叙事层 | `cast`, `factions`, `threads`, `chapters` | 人物长期状态、势力和最终手稿 |
| 内容层 | `WuxiaContentRegistry` | 已安装内容包和合并规则 |

加载器同时检查顶层版本、生涯版本、沙盘模式、世界人物、关系、章节和活动数组。不符合 v6 契约的旧存档会被拒绝，不会被悄悄解释成新世界。

## 14. 内容包与 MOD 边界

`WuxiaContentPack` 是当前可执行的构建期 MOD 协议：

- `id`, `version`, `label`：身份和版本；
- `agendas`：新路线；
- `opportunities`：新盛事、秘境或聚会；
- `characters`：人物、目标、武学、住所和日常路线；
- `locations`：新地点和道路；
- `activities`：既有活动种类的内容元数据；
- `rules`：章节长度、活动数量、自创和创派门槛。

注册器拒绝重复 ID。建世界时还会验证：

- 新地点引用的连接必须存在；
- 扩展道路会自动补上反向连接；
- 所有地点必须能从核心路网抵达；
- 人物住所、日常地点和盛事地点必须存在；
- 内容包来源 ID 会随人物、机会和路线进入存档。

`exampleContentPack.ts` 是最小可运行参考。它加入“沿河访信”路线、河灯旧埠、河灯夜会、信使罗枕河和一组规则覆盖；测试会确认新地点与听雨渡双向连接，人物和盛事确实落在新地点。

当前协议故意不从浏览器加载任意脚本。数据包可扩人物、地点、路线、机会和阈值；新增全新 `ActivityKind` 或特殊结算行为仍需在引擎中增加受测试的适配器。这条边界避免 MOD 函数破坏确定性存档，同时保留逐步扩展玩法的主框架。

## 15. 验收标准

`pnpm run wuxia:test` 覆盖：

- 主动秘籍追查和线索结算；
- 自创招式不污染选择前状态；
- 真实人物传艺名册与序列化；
- 正式创派和传承归属；
- 示例内容包的人物、路线、机会、地点和规则；
- 重复 ID、孤立地点和悬空人物地点拒绝；
- 已参加盛事不会重新开放。

`pnpm run wuxia:verify` 使用系统 Chrome 覆盖：

- 姓名和世界种子独立随机；
- 27 寸 2K 字号下限；
- 路线、行程、场景、独立结算、章末和下一章；
- 提前赴会与正式参会；
- 人物意图、追踪、异派战斗、辨招和势力交手账；
- 第 13 幕以后继续、生涯刷新恢复；
- 自创、两次真实人物传艺和正式创派；
- 桌面和 390px 移动布局；
- 选择和结算不显示精确概率、掷签或检定术语；
- 小说正文、结算与交手实录不显示原始战斗数值、调试术语或内部势力 ID；
- 专门武学谱可以展示玩家主动查阅的招式属性与修习数据，但来源必须使用世界内名称；
- 截图非纯色、非透明、非近黑，控制台错误和失败请求为零。

`window.advanceTime()` 不推进世界，因为该游戏只在玩家明确选择后推进日期；等待时长不会改变人物位置或结局。

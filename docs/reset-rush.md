# RESET / 开蹬！v0.6 · 工作室协作

1 位玩家与 3 位电脑开发者竞争的德式跑分桌游。42 天标准局、21 天短局；每个人从一个 $20 账号、$480 现金和一张初始银行券开始。新局先打开账号管理。

## 为什么重做核心循环

v3 把买号、接单、开发和模型运行拆成模拟时间、真人精力、账号额度，解决了 Turbo 超出项目进度反而浪费的问题。但每个账号与线程都要逐一配置，每天得多次推进时间。v4 保留三项资源，改为**接单、设置全局策略、收工揭牌**；工作室自动排队、跨账号换号和连续运行。玩家仍可在关键时刻停下，用银行券或切换开发节奏。

2026-09-26 阅读的官方依据：

- [Speed](https://learn.chatgpt.com/docs/agent-configuration/speed)：加速以更多 credits 换更快响应，不应凭空增加 bug。
- [Models](https://learn.chatgpt.com/docs/models)：更深思考会多花时间与 tokens；Ultra 涉及分工并行；Luna 适合清晰、可重复的任务。
- [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)：可以同时运行独立任务，让后台任务与前台工作分开。

文档用于确定资源关系，游戏不是产品计费模拟器。速度、额度、能力、免费 Luna 和套餐容量均为游戏平衡数值。为了保留用户要求的独立选择，三个模型均保留 Low–Ultra；官方页面目前说明 GPT-6 Luna 只到 Max。游戏 Turbo 的速度 ×2 也是设计值，不能当作真实产品承诺。

## 一天怎么玩

每天 09:00–17:00，共 **480 模拟分钟、12 精力**。现实等待、阅读、选配置均不走时间。接下项目会自动进入工作室；设定并行线程数量、账号使用顺序和全局开发节奏后，点“收工并揭牌”就会让所有玩家工作到 17:00。可选“到关键时刻”会在你的项目交付或所有运行线程缺额时停下；没有关键节点就推进到收工。

| 操作 | 真人精力 | 模拟分钟 | 效果 |
| --- | ---: | ---: | --- |
| 买号、升级、续费、到期方案 | 0 | 0 | 仅扣所需现金 |
| 接一个项目 | 1 | 0 | 不限持有项目数，可集中接多单 |
| 托管一条有项目的线程 | 2 | 0 | 自动排队，可设同时运行 0–6 条；当天调低再调高不重复收费 |
| 调整全局节奏、账号策略 | 0 | 0 | 全部线程立即采用新配置，余额用完自动换号 |
| 暂停全部线程 | 0 | 0 | 将数量设为 0；项目进度与额度保留 |
| 跨天继续托管线程 | 每条 2 | 0 | 当天早晨从 12 精力里预留 |
| 用银行券 | 0 | 0 | 补满选中账号，缺额线程可继续 |
| 休息，每天一次 | 恢复 3 | 60 | 后台任务继续跑，上限 12 精力 |
| 手写外包 | 1 | 60 | +$25，后台任务继续跑 |
| 亲自排障 | 2 | 30 | 清除所选项目最多 2 bug；后台照跑 |
| 主动弃单 | 0 | 0 | −2 VP |

最多 6 条托管线程，一条线程串行，不同线程并行；同一账号可以带多条线程，共享额度。工作室保留正在进行的项目，待办项目按截止日优先、再按剩余工作量分散到线程；先给不同项目各分配一条主线程，空闲 agent 再协助剩余工作量大的项目。同一项目可设最多 1 / 2 / 3 人，2 人合计 1.7×、3 人 2.2× 速度，每人仍占 2 精力；不重复记进度、扣额度、检查 bug 或发放奖励。多人只缩短时间，每份有效工作仍只扣一次额度。新局默认每项最多 2 人、共 1 条线程；旧局维持每项 1 人。完成项目自动发布并立刻做下一项，最后一项完成则停止扣额。所有分钟都按实际工作结算，不预付“一整块开发行动”，未消耗额度仍属于账号。

缺额只暂停付费线程；可用账号都缺额时，补额即续跑。也可切换到 Luna Medium、关闭 Turbo，即便订阅暂停也能工作。已完成或已暂停的线程次日不预留精力；重新开工收 2 精力。每日接单与托管的精力让无限免费并行有实际取舍，而不是靠模型请求次数硬卡住玩家。

“收工并揭牌”会跑完剩余分钟，再揭牌，不会跳过后台工作。夜间队列停止；下一天继续。电脑每半小时检查公开市场、队列、预算与赠礼概率，使用同样资源和规则，玩家仅点免费管理按钮不会触发电脑额外行动。

## 自动账号策略

| 策略 | 路由规则 |
| --- | --- |
| 快重置优先（默认） | 先花自然重置日最近的账号 |
| 更多额度优先 | 先用剩余额度数值最多的账号，每个模拟分钟及任务节点重新比较，让各号余额逐渐接近；余额相同则分散线程 |
| 指定账号优先 | 指定账号有额度就集中花，用完才换号 |
| 快耗尽优先 | 先清掉剩余额度最少的账号 |
| 晚到期优先 | 先用订阅有效期最久的账号 |
| 按比例均衡 | 按套餐剩余额度比例分散线程，减少同号拥挤 |

仅在有效订阅且有额度的账号之间路由；额度耗尽会在同一个模拟分钟内切到下一个账号。免费 Luna 不消耗额度，也不需要有效订阅。线程数增加会增加并行速度和每日真人精力开销，但不会凭空产生额度。

例如 $200 号约剩 17%、$20 号剩 100% 时，“更多额度优先”结合 20× 倍率，会先用大号，“按比例均衡”单线程会先用剩余比例 100% 的号。目前普通强制重置会补满全部有效账号，因此总消耗相同时，总补回额度与余额如何分布无关；新策略改变的是各号消耗分布，不额外制造补额奖励。

## 模型 × 思考 × Turbo

| 模型 | 基础进度/小时 | 每进度额度 | 能力 |
| --- | ---: | ---: | ---: |
| Luna | 4.5 | 0 | 1 |
| Sol | 10.8 | 0.16 | 2 |
| Astra | 18 | 0.4 | 3 |

| 思考 | 速度倍率 | 额度/进度倍率 | 能力修正 | Luna 每进度额度 |
| --- | ---: | ---: | ---: | ---: |
| Low | 1.2 | 0.75 | −0.5 | 0 |
| Medium | 1 | 1 | 0 | 0 |
| High | 0.9 | 1.5 | +0.5 | 0.035 |
| XHigh | 0.8 | 2 | +1 | 0.06 |
| Max | 0.65 | 2.6 | +1.25 | 0.1 |
| Ultra | 1.5 | 3 | +1.5 | 0.16 |

Turbo 速度 ×2、**每进度**额度 ×2.5，免费基础配置加速后的最低单价为 0.0625。快乐日 Turbo 额度打 75 折。Ultra 抽象为多部分协作攻坚，允许吞吐提升；High–Max 则以更多时间换思考能力。

例：Sol Medium 做 10.8 进度，普通模式需要 60 分钟、1.728 额度；Turbo 需要 30 分钟、4.32 额度。Astra Ultra + Turbo 可以快速烧额度，但没有重置预告时这么做通常不划算。基准预估包含当前已知返工，未包含未来随机 bug。

项目有独立的工作量与难度。能力不足时每 20 进度的 bug 概率为 `clamp(round((需求难度 + 隐藏集成难点 − 能力) × 30), 0, 80)%`。小于 20 的尾段按工作量降低概率。换配置不会抹除之前累计的风险；Turbo 不改变相同工作量的风险。每个 bug 完工后自动返工 12 进度，消耗对应时间与额度；返工不会再次制造 bug，确保免费路线始终可完成。手动排障适合抢当天发布奖励或期限。

## 按项目自动配置与工作室经验

“项目配置”保留统一配置，另增**自动稳妥**选项。开启后，对每个队首项目分别枚举当前模型与思考强度，选择估计风险上界为 0 的最低每进度额度配置；同价优先速度更快者。模型能力、价格升级后继续适用。Turbo 独立开关；点击慢跑/均衡/冲刺预设或手动改模型、强度会返回统一配置。缺额时保持配置等待，不暗中降到高风险 Luna。自动稳妥侧重省额，不承诺最快；没有足够安全余量时用最强配置，并明确提示可能返工。

项目需求等级是初始估计。约三分之一非教学项目带额外 0.5 集成难点，由局种子与项目 ID 决定，首次摸底前不公开。项目完成首段 20 进度、发现 bug 或实际完工后揭示难点，亲自排障也会揭示。模型按实际有效工作量（含返工）累计实测，60 进度后校准当前代能力；同一模型不同思考强度共享经验，开源速度加成与此经验独立。换代需重新校准该模型，单纯降价不丢经验。

摸底期自动策略只读取需求范围 0–0.5 及模型能力 ±0.5 的估计，按悲观边界留余量；模型实际能力仍按游戏数值固定。项目与模型都熟悉后，界面才显示精确风险，自动配置会在下个工作节点降档或升档。bug 风险仍累计在项目上，切换强配置不会抹掉之前埋下的风险。公开 `render_game_to_text` 隐去未知集成难点和内部风险累积；电脑也按自身实测与公开估计挑配置。

一个项目的多个 agent 在工作台合并成一张小队卡，显示合计速度、参与账号与摸底状态。玩家只调总线程数和单项目协作上限，系统负责分配与收工结算，不需要逐项目挑模型或安排子任务。“工作室经验”可展开查看，不新增资源或手动研究操作。

旧 v5 存档通过独立 `workflowRules` 标记迁移一次，保留进度、现金、券、队列、随机状态及配置。既有项目与模型视作已经掌握（原版本来就公开精确风险），保留统一配置与每项 1 人；新接项目和新模型开始积累新经验。

## 账号、银行券与两个时钟

下面的容量是引擎归一化单位，玩家界面只显示整数百分比。套餐严格采用用户要求的 1× / 5× / 20×；同一配置、同一平台口径下保持该比例。

| 订阅 | 补满容量 | 订阅期限 | 自然重置 |
| --- | ---: | --- | --- |
| $20 | 24（1×） | 30 天 | 开通日起每 7 天 |
| $100 | 120（5×） | 30 天 | 开通日起每 7 天 |
| $200 | 480（20×） | 30 天 | 开通日起每 7 天 |

最多 3 个账号。升级只补套餐差价、增加容量差额，保留到期与自然重置日。免费安排到期按任意档续费，或不续订。自动续订按账号顺序扣钱，补满并重新计 30 天和 7 天；不足则暂停，只尝试一次。暂停后可手动选仍在售档位续开。新号不送银行券。

自然 reset、直接 reset、银行券都只补到容量、不叠加余额。直接 reset 与银行券不改变自然周期。券绑定账号，发放日加 30 的早晨失效；持有无上限、每号每天最多用 1 张（游戏节奏规则），优先用最早到期的。停订不会冻结券的有效期。

双号策略仍成立：集中烧一个号、用它的券，另一个等自然恢复；或让两个号并行赶 Game Jam/公司交付。买新号本身免费操作，却有真实现金成本；它解决额度供给，不自动增加真人可托管的精力。

## 事件、项目与胜利点

前四天固定为 30% 谜语、100% 赠礼预告、平静、Turbo 快乐日。只给初始账号 1 张教学券，第 4 天不再固定送券。常规事件牌堆移除全员银行券卡，保留它用于兼容旧存档当日消息；其余 13 种非模型事件各 1 张，再加 3 张平静、2 张爬山（共 18 张，停售触发后移除该卡）。消息堆不放回抽取，模型事件按原有发布时点穿插。

夜间先按消息概率决定是否赠礼，再从 **9 张普通 reset、1 张 banked reset** 中不放回抽取；牌堆构成公开，抽空重洗。10% 是完整牌堆中的银行牌占比，不是每日发券率；剩余牌会改变下一抽概率。谜语 30%、Soon 60%、省略号 10%、builders deserve more 40%、Game Jam 20%；两张明确承诺仍为 100%，额度口径事件不再附送重置。五次模型事件的赠礼率依次为 20% / 0% / 35% / 20% / 50%。刚用券又遇免费 reset 会记录同日撞车，但不重复扣分。

现实参考：[官方 Pricing](https://learn.chatgpt.com/docs/pricing)（2026-09-27 查阅，原 developers.openai.com/codex/pricing 跳转至此）说明限时邀请活动奖励 banked rate-limit reset，到账后 30 天可用；活动可邀请三人并不是持券上限。公开说明未确认统一库存上限，也未给出固定赠券日历或概率。上述教学券、每日用券限制、事件权重及 9:1 牌堆均为游戏平衡设定，不代表官方实际政策或统计。

供给规则独立修订，继续读取 v5 存档。旧局保留持券、项目、现金、今日消息与结算，只清空尚未抽取的旧事件堆和重置堆，在下一次需要抽牌时按新规则洗牌；迁移本身不消耗随机数，且只执行一次。

项目从 42 进度的新手记账本，到 560 进度的简单大型推箱子，规模有明显差别。碉游多声望；个人项目每款每周 +$15；每发布一款开源项目全模型速度 +8%，最多 +24%；公司项目高回款，接单后第 8 天收工前交付，次日超期撤单 −3 VP。每周基础收入 $35。

计分保留作品与公共奖项，现金和算力点只是封顶加分。首发碉游 +5、首位发布三类作品 +6、首位积累 500 算力点 +5；四类多样性 +12 或三类 +5；现金每 $100 和算力点每 120 各 +1，两项各封顶 10。未完成项目不计分。

三位电脑有不同偏好：开源效率、赶工首发、双号银行券。所有策略都可以积累现金扩号，避免某个策略仅因写死账号数而必胜；不读取未来事件、牌序或 PRNG。

## 平台风向：增加决策，不增加每日点击

工作室仍只有三个模型位置和三档快捷开发节奏。新版本自动替换同系列模型，现有线程、思考强度与 Turbo 设置继续使用；没有解锁按钮、升级费用或逐线程迁移。

| 阶段 | 永久效果（相对初代） |
| --- | --- |
| 5.0 起步 | Luna / Sol / Astra 的初始能力分别为 1 / 2 / 3 |
| 5.6 Luna 发布 | 能力 +0.5，速度 +20%，付费费率 115% |
| 5.6 Luna 降价 | 能力、速度不变，付费费率降至 65% |
| 6 Sol 发布 | 能力 +1，速度 +25%，费率 75% |
| 6 Luna 发布 | 能力 +1，速度 +50%，费率 45%；免费 Medium 可处理基础常规任务，集成难点仍需摸底 |
| 6 Astra 发布 | 能力 +1，速度 +20%，费率 85%；Medium 可处理基础攻坚任务，集成难点仍需摸底 |

首场发布在 D6，之后每隔 4–6 天推进一个阶段。具体后续日期对玩家与 AI 隐藏。发布牌可以同时带赠礼概率，让“等降价”与“重置前先蹬”发生取舍。以上为虚构桌游进程，不宣称真实发布时间或真实能力差异。

**停售窗口。** 随机消息可能宣布 $200 将于两天后早晨停售，今天和明天仍可新开或升级。截止后禁止新开、升级、断订重开以及预约到期升档；已预约但尚未完成的升档自动改为原档续费。仍在 $200 的账号可以持续自动续费，资金不足、停订或实际降档后失去资格。规则同样约束 AI；停售不会强制降档或没收已付费权益。

**百分比与暗改。** 后台将有效额度口径设在基准的 80%、100%、120% 之一，社区事件可能换成另一个值；当前可见百分比不变，同等工作掉额速度改变。所有套餐同时变化，5× / 20× 比例不变，免费 Luna 仍可运行。公开消息不给出实际方向与精确倍数。

**自动观察。** 账号下默认折叠“用量观察”，累积当前配置的模拟 k token 与整数百分点变化。至少掉 2 个百分点后显示同配置满额可支持的 token 区间，按整数读数 ±1 个百分点给出误差；不是把隐藏容量直接换个名字显示。Turbo 增加单位 token 扣额，模型降价降低扣额，二者不虚增相同工作产生的 token。换配置、补满、升档、模型发布或口径变化重新采样。刷新保留采样，分段推进与一次推进一致。当前估计不能保证未来额度。

胜利点中的原“已用额度”改称算力点，按模型降价前的开发消耗计量，保留原有封顶与公共奖项；口径收紧不会凭空增加得分。公开文字状态不含隐藏口径、精确余额、未来发布时间或真实补额总量。

## 实现与存档

纯 TypeScript 模拟与 React DOM 卡牌分离。按整数分钟推进，分钟内部在项目结束、风险检查点、返工完成、同账号额度耗尽处切分，各线程同时扣额。耗尽时按各自消耗率共享最后一小段额度。更换推进按钮粒度不影响随机结果或对手进度。

`render_game_to_text()` 包含公共时间、精力、队列状态、任务和账号，不暴露 PRNG 或未来牌序。`advanceTime(60000)` 明确推进 1 模拟分钟，普通浏览器帧和现实时间不会推进。所有数据可序列化，刷新或关闭页面不偷偷跳天。

# RESET / 开蹬！v0.9 · 近期模型

1 位玩家与 3 位电脑开发者竞争的德式跑分桌游。42 天标准局、21 天短局；每个人从一个 $20 账号、$480 现金和一张初始银行券开始。新局先打开账号管理。

## 为什么重做核心循环

v3 把买号、接单、开发和模型运行拆成模拟时间、真人精力、账号额度，解决了 Turbo 超出项目进度反而浪费的问题。但每个账号与线程都要逐一配置，每天得多次推进时间。v4 保留三项资源，改为**接单、设置全局策略、收工揭牌**；工作室自动排队、跨账号换号和连续运行。玩家仍可在关键时刻停下，用银行券或切换开发节奏。

2026-09-26 阅读的官方依据：

- [Speed](https://learn.chatgpt.com/docs/agent-configuration/speed)：加速以更多 credits 换更快响应，不应凭空增加 bug。
- [Models](https://learn.chatgpt.com/docs/models)：更深思考会多花时间与 tokens；Ultra 涉及分工并行；Luna 适合清晰、可重复的任务。
- [Worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)：可以同时运行独立任务，让后台任务与前台工作分开。

文档用于确定资源关系，游戏不是产品计费模拟器。Low–Ultra 表示思考、拆分、重试、自测的综合投入；免费 Luna、Turbo 倍率、能力与额度数值均为游戏规则，不是所有模型统一支持的 API 参数。

## 一天怎么玩

每天 09:00–17:00，共 **480 模拟分钟、12 精力**。现实等待、阅读、选配置均不走时间。接下项目自动进入工作室；设定同时运行的 AI 对话数、账号策略与开发节奏后，主按钮“推进开发”在项目交付、新增缺额等待或精力等待时停下。已经没有可运行的 AI 对话时再点也不走钟，不会空跑到晚上。部分付费对话缺额、免费 Luna 仍在运行时会先停下给玩家补给机会，再次推进可让免费任务继续。没有中间节点的持续开发最多运行至 17:00。

| 操作 | 真人精力 | 模拟分钟 | 效果 |
| --- | ---: | ---: | --- |
| 买号、升级、续费、到期方案 | 0 | 0 | 仅扣所需现金 |
| 接一个项目 | 1 | 0 | 不限持有项目数，可集中接多单 |
| 托管一条有项目的线程 | 1–2 | 0 | 能包办架构、自测的配置 1 点；需要人工跟进 2 点。09:00 尚未开工可退还预留；开工后同日只补差额，不退已用精力 |
| 调整全局节奏、账号策略 | 0 | 0 | 未单独配置的项目采用新配置，余额用完自动换号 |
| 暂停全部线程 | 0 | 0 | 将数量设为 0；项目进度与额度保留 |
| 跨天继续托管线程 | 每条 1–2 | 0 | 早晨模型更新后按当天项目与配置重新预留 |
| 用银行券 | 0 | 0 | 补满选中账号，缺额线程可继续 |
| 休息，每天一次 | 恢复 3 | 60 | 后台任务继续跑，上限 12 精力 |
| 手写外包 | 1 | 60 | +$25，后台任务继续跑 |
| 亲自排障 | 2 | 30 | 清除所选项目最多 2 bug；后台照跑 |
| 主动弃单 | 0 | 0 | −2 VP |

最多 6 条托管线程，一条线程串行，不同线程并行；同一账号可以带多条线程，共享额度。工作室保留正在进行的项目，待办项目按截止日优先、再按剩余工作量分散到线程；先给不同项目各分配一条主线程，空闲 agent 再协助剩余工作量大的项目。同一项目可设最多 1 / 2 / 3 个 AI 对话合作，2 个合计 1.7×、3 个 2.2× 速度，每个对话占真人 1–2 精力；不重复记进度、扣额度、检查 bug 或发放奖励。多人只缩短时间，每份有效工作仍只扣一次额度。新局默认每项最多 2 个 AI 对话合作、同时开 1 个；早期旧局维持每项最多 1 个。完成项目自动发布并立刻做下一项，最后一项完成则停止扣额。所有分钟都按实际工作结算，不预付“一整块开发行动”，未消耗额度仍属于账号。

缺额只暂停付费线程；可用账号都缺额时，补额即续跑。也可切换到 Luna Medium、关闭 Turbo，即便订阅暂停也能工作。已完成或已暂停的线程次日不预留精力；重新开工按当日配置预留 1–2 精力。每日接单与托管的精力让无限免费并行有实际取舍，而不是靠模型请求次数硬卡住玩家。

“准备收工”先显示剩余时间、精力和有效银行券，说明免费 Luna 与手写外包仍可使用。取消不改变时间与资源；确认才让后台任务跑完剩余分钟并揭牌，中途不再停下等待补给。揭牌仍属于今天，玩家点“下一天”才进入次日。额度归零本身不会结束当天。电脑每半小时检查公开市场、队列、预算与赠礼概率，使用同样资源和规则，玩家仅点免费管理按钮不会触发电脑额外行动。

## 品质与省心：自动结算，无需额外操作

同一任务，只要能力达到要求，各档都能安全完成；超出要求的能力还用于架构、细节和自测。作品按全程有效开发量积累品质：**合格**基础收益、**精良**现金与声望 +20%、**精品** +40%，各项奖励向下取整。卡牌显示基础奖励，线程显示当前配置继续做到完工时的保守品质预估，履历与交付日志显示实际收入。Game Jam 的额外 VP 在品质奖励之后相加。

模型/思考配置的能力比项目需求高出至少 1 档（采用公开的保守估计），当天每条线程只需 **1 精力**；否则 **2 精力**。未知项目与未校准模型保留余量。09:00 且尚未推进任何时间时，托管精力是可重排的预留：调少 AI 对话或切更省心的配置会释放差额，支持没有精力明细的旧版 0/12 早晨存档。开工后按每条线程用过的最高需求计费：从省心档切到费心档或接续更难项目时补 1 点；切回、暂停再开不退款也不重复收取。精力不足时线程显示“等待精力”，不做工、不扣额；其他线程仍能工作。次日按早间新模型与当前配置重新计算。手动派工接口保留至少 1 点重新沟通费用；默认工作室不需要逐条派工。

原有“项目配置”下拉框新增 **自动精品 · 品质与省心**：逐项选保守能力余量至少 1.5 的最低每进度消耗配置；同价优先速度，无法达到时用最强配置尽力优化，并显示真实预估。**自动稳妥**仍选够用的最低消耗配置。两者都自动学习、换代，Turbo 独立；不新增面板、额外货币或验收点击。便宜配置适合长线省额，强配置能用额度换品质和省心，但不是每个攻坚项目都能达到精品。

实现口径：每份有效开发量累积 `clamp((实际能力 − 实际需求) / 2, 0, 1)` 的品质；交付时品质量 / 总工作量达到 0.35 为精良、0.75 为精品。中途换档按各自完成比例结算，最后一刻切强模型不能补刷；返工不累积品质，Turbo 和多人不直接加品质或重复奖励。需求尚未摸清时，界面和公共文本状态不暴露隐藏品质量。

v5 存档键保持不变，通过 `qualityRules` 独立迁移：保留现金、VP、进度、随机序列和已花精力，旧进度不追补品质；旧日内线程视为已预留 2 点；开工后不追退，09:00 尚未开工则可按新版规则调整预留。历史作品无品质记录，履历按基础奖励展示（历史 Game Jam 明细无法重建），实际玩家资产不受影响。

## 界面与精力提示

“同时开几个 AI 对话”是整个工作室的并发预算；“单个项目最多几个 AI 对话合作”只是每项上限，不是额外人手或预留。项目卡下默认折叠“项目单独设置”，可为选中项目设置模型、投入强度、Turbo、合作上限；未覆盖的字段跟随全局，恢复默认一键生效。队列中的项目也可设置，开始时自动应用。

精力明细展示每日 12 点、AI 预留/跟进、接单、其他操作、休息恢复与旧记录。接单卡预告接单 1 点及新启动 AI 可能预留的费用；精力为零时明确提示减少早晨预留、休息或次日恢复的条件。免费 Luna 不耗额度，但跟进它仍可能要补精力，也不能保证困难任务无 bug。

弹窗固定标题与关闭按钮，只滚动内容；作品履历、账号管理与玩法规则均使用相同结构。时钟旁提供账号/银行券、免费 Luna 配置和手写外包入口。全局免费预设不会覆盖项目单独配置，旁边提示去该项目恢复跟随或切换配置。

## 自动账号策略

| 策略 | 路由规则 |
| --- | --- |
| 快重置优先（默认） | 先花自然重置日最近的账号 |
| 更多额度优先 | 先用剩余额度数值最多的账号，每个模拟分钟及任务节点重新比较，让各号余额逐渐接近；余额相同则分散线程 |
| 指定账号优先 | 指定账号有额度就集中花，用完才换号 |
| 快耗尽优先 | 先清掉剩余额度最少的账号 |
| 晚到期优先 | 先用订阅有效期最久的账号 |
| 按比例均衡 | 按套餐剩余额度比例分散线程，减少同号拥挤 |

仅在有效订阅且有额度的账号之间路由；额度耗尽会在同一个模拟分钟内切到下一个账号。免费 Luna 不消耗额度，也不需要有效订阅。线程数增加会增加并行速度和每日真人精力开销，但不会凭空产生额度。

例如 $200 号约剩 17%、$20 号剩 100% 时，“更多额度优先”结合 20× 倍率，会先用大号，“按比例均衡”单线程会先用剩余比例 100% 的号。目前普通强制重置会补满全部有效账号，因此总消耗相同时，总补回额度与余额如何分布无关；新策略改变的是各号消耗分布，不额外制造补额奖励。

## 模型 × 思考 × Turbo

| 模型 | 基础进度/小时 | 每进度额度 | 能力 |
| --- | ---: | ---: | ---: |
| Luna | 4.5 | 0 | 1 |
| Sol | 10.8 | 0.16 | 2 |
| Astra | 18 | 0.4 | 3 |

| 思考 | 速度倍率 | 额度/进度倍率 | 能力修正 | Luna 每进度额度 |
| --- | ---: | ---: | ---: | ---: |
| Low | 1.2 | 0.75 | −0.5 | 0 |
| Medium | 1 | 1 | 0 | 0 |
| High | 0.9 | 1.5 | +0.5 | 0.035 |
| XHigh | 0.8 | 2 | +1 | 0.06 |
| Max | 0.65 | 2.6 | +1.25 | 0.1 |
| Ultra | 1.5 | 3 | +1.5 | 0.16 |

Turbo 速度 ×2、**每进度**额度 ×2.5，免费基础配置加速后的最低单价为 0.0625。快乐日 Turbo 额度打 75 折。Ultra 抽象为多部分协作攻坚，允许吞吐提升；High–Max 则以更多时间换思考能力。

例：Sol Medium 做 10.8 进度，普通模式需要 60 分钟、1.728 额度；Turbo 需要 30 分钟、4.32 额度。Astra Ultra + Turbo 可以快速烧额度，但没有重置预告时这么做通常不划算。基准预估包含当前已知返工，未包含未来随机 bug。

项目有独立的工作量与难度。能力不足时每 20 进度的 bug 概率为 `clamp(round((需求难度 + 隐藏集成难点 − 能力) × 30), 0, 80)%`。小于 20 的尾段按工作量降低概率。换配置不会抹除之前累计的风险；Turbo 不改变相同工作量的风险。每个 bug 完工后自动返工 12 进度，消耗对应时间与额度；返工不会再次制造 bug，确保免费路线始终可完成。手动排障适合抢当天发布奖励或期限。

## 按项目自动配置与工作室经验

“项目配置”保留统一配置，另增**自动稳妥**选项。开启后，对每个队首项目分别枚举当前模型与投入强度，选择估计风险上界为 0 的最低每进度额度配置；同价优先速度更快者。模型能力、价格升级后继续适用。Turbo 独立开关；点击慢跑/均衡/冲刺预设或手动改模型、强度会返回统一配置。缺额时保持配置等待，不暗中降到高风险 Luna。自动稳妥侧重省额，不承诺最快；没有足够安全余量时用最强配置，并明确提示可能返工。

项目需求等级是初始估计。约三分之一非教学项目带额外 0.5 集成难点，由局种子与项目 ID 决定，首次摸底前不公开。项目完成首段 20 进度、发现 bug 或实际完工后揭示难点，亲自排障也会揭示。模型按实际有效工作量（含返工）累计实测，60 进度后校准当前代能力；同一模型不同投入强度共享经验，开源速度加成与此经验独立。换代需重新校准该模型，单纯降价不丢经验。

摸底期自动策略只读取需求范围 0–0.5 及模型能力 ±0.5 的估计，按悲观边界留余量；模型实际能力仍按游戏数值固定。项目与模型都熟悉后，界面才显示精确风险，自动配置会在下个工作节点降档或升档。bug 风险仍累计在项目上，切换强配置不会抹掉之前埋下的风险。公开 `render_game_to_text` 隐去未知集成难点和内部风险累积；电脑也按自身实测与公开估计挑配置。

一个项目的多个 agent 在工作台合并成一张小队卡，显示合计速度、参与账号与摸底状态。玩家只调总线程数和单项目协作上限，系统负责分配与收工结算，不需要逐项目挑模型或安排子任务。“工作室经验”可展开查看，不新增资源或手动研究操作。

旧 v5 存档通过独立 `workflowRules` 标记迁移一次，保留进度、现金、券、队列、随机状态及配置。既有项目与模型视作已经掌握（原版本来就公开精确风险），保留统一配置与每项最多 1 个 AI 对话；新接项目和新模型开始积累新经验。

最多 3 个账号。升级只补套餐差价、增加容量差额，保留到期与自然重置日。免费安排到期按任意档续费，或不续订。自动续订按账号顺序扣钱，补满并重新计 30 天和 7 天；不足则暂停，只尝试一次。暂停后可手动选仍在售档位续开。新号不送银行券。

自然 reset、直接 reset、银行券都只补到容量、不叠加余额。直接 reset 与银行券不改变自然周期。券绑定账号，发放日加 30 的早晨失效；持有与同一账号每天使用次数均无上限，优先用最早到期的。停订不会冻结券的有效期。

双号策略仍成立：集中烧一个号、用它的券，另一个等自然恢复；或让两个号并行赶 Game Jam/公司交付。买新号本身免费操作，却有真实现金成本；它解决额度供给，不自动增加真人可托管的精力。

## 事件、项目与胜利点

前四天固定为 30% 谜语、100% 赠礼预告、平静、Turbo 快乐日。只给初始账号 1 张教学券，第 4 天不再固定送券。常规事件牌堆移除全员银行券卡，保留它用于兼容旧存档当日消息；其余 13 种非模型事件各 1 张，再加 3 张平静、2 张爬山（共 18 张，停售触发后移除该卡）。消息堆不放回抽取，模型事件按原有发布时点穿插。

夜间先按消息概率决定是否赠礼，再从 **9 张普通 reset、1 张 banked reset** 中不放回抽取；牌堆构成公开，抽空重洗。10% 是完整牌堆中的银行牌占比，不是每日发券率；剩余牌会改变下一抽概率。谜语 30%、Soon 60%、省略号 10%、builders deserve more 40%、Game Jam 20%；两张明确承诺仍为 100%，额度口径事件不再附送重置。新局三个可能的模型事件赠礼率为 35% / 20% / 50%；tech-1/2 仅保留旧存档兼容。刚用券又遇免费 reset 会记录同日撞车，但不重复扣分。

现实参考：[官方 Pricing](https://learn.chatgpt.com/docs/pricing)（2026-09-27 查阅，原 developers.openai.com/codex/pricing 跳转至此）说明限时邀请活动奖励 banked rate-limit reset，到账后 30 天可用；活动可邀请三人并不是持券上限。公开说明未确认统一库存上限，也未给出固定赠券日历或概率。上述教学券、事件权重及 9:1 牌堆均为游戏平衡设定，不代表官方实际政策或统计。

供给规则独立修订，继续读取 v5 存档。旧局保留持券、项目、现金、今日消息与结算，只清空尚未抽取的旧事件堆和重置堆，在下一次需要抽牌时按新规则洗牌；迁移本身不消耗随机数，且只执行一次。

项目池共 60 种题材，四类各 15 种，包括暖心晚安回复 AI、同人自走棋、直播投票插件、直播工具与其他个人/开源/公司项目。补牌先避开市场与所有玩家正在开发的同名项目，再优先选全局较少做过的题材；池耗尽时有限回退，不强行改名或删除旧局已有项目。项目从 42 进度的新手记账本，到 560 进度的简单大型推箱子，规模有明显差别。碉游多声望；个人项目每款每周 +$15；每发布一款开源项目全模型速度 +8%，最多 +24%；公司项目高回款，接单后第 8 天收工前交付，次日超期撤单 −3 VP。每周基础收入 $35。

计分保留作品与公共奖项，现金和算力点只是封顶加分。首发碉游 +5、首位发布三类作品 +6、首位积累 500 算力点 +5；四类多样性 +12 或三类 +5；现金每 $100 和算力点每 120 各 +1，两项各封顶 10。未完成项目不计分。

三位电脑有不同偏好：开源效率、赶工首发、双号银行券。所有策略都可以积累现金扩号，避免某个策略仅因写死账号数而必胜；不读取未来事件、牌序或 PRNG。

## 平台风向：增加决策，不增加每日点击

工作室仍只有三个模型位置和三档快捷开发节奏。模型席位开放后自动更新到相应真实型号，现有线程、投入强度与 Turbo 设置继续使用；没有解锁按钮、升级费用或逐线程迁移。

| 阶段 | 永久效果（相对开局） |
| --- | --- |
| 起步 | GPT-5.6 Luna / GPT-5.6 Sol / GPT-6 Astra，能力 1 / 2 / 3 |
| 6 Sol | 主力能力 +1，速度 +25%，配额费率 50% |
| 6 Luna（Sol 同步就绪） | 轻量能力 +1，速度 +50%，付费配额费率 45%；免费配置保留；尚未开放的 6 Sol 同时上线 |
| 虚构 6.1 Astra | 攻坚能力 +1，速度 +20%，费率 85%；明确显示虚构标识 |

发布消息仍可能附带赠礼，让新模型降价与重置抢跑产生取舍。仅三个原有选择自动升级，不增加每日点击或手动迁移。

**停售窗口。** 随机消息可能宣布 $200 将于两天后早晨停售，今天和明天仍可新开或升级。截止后禁止新开、升级、断订重开以及预约到期升档；已预约但尚未完成的升档自动改为原档续费。仍在 $200 的账号可以持续自动续费，资金不足、停订或实际降档后失去资格。规则同样约束 AI；停售不会强制降档或没收已付费权益。

**百分比与暗改。** 后台将有效额度口径设在基准的 80%、100%、120% 之一，社区事件可能换成另一个值；当前可见百分比不变，同等工作掉额速度改变。所有套餐同时变化，5× / 20× 比例不变，免费 Luna 仍可运行。公开消息不给出实际方向与精确倍数。

**自动观察。** 账号下默认折叠“用量观察”，累积当前配置的模拟 k token 与整数百分点变化。至少掉 2 个百分点后显示同配置满额可支持的 token 区间，按整数读数 ±1 个百分点给出误差；不是把隐藏容量直接换个名字显示。Turbo 增加单位 token 扣额，模型降价降低扣额，二者不虚增相同工作产生的 token。换配置、补满、升档、模型发布或口径变化重新采样。刷新保留采样，分段推进与一次推进一致。当前估计不能保证未来额度。

胜利点中的原“已用额度”改称算力点，按模型降价前的开发消耗计量，保留原有封顶与公共奖项；口径收紧不会凭空增加得分。公开文字状态不含隐藏口径、精确余额、未来发布时间或真实补额总量。

## 实现与存档

纯 TypeScript 模拟与 React DOM 卡牌分离。按整数分钟推进，分钟内部在项目结束、风险检查点、返工完成、同账号额度耗尽处切分，各线程同时扣额。耗尽时按各自消耗率共享最后一小段额度。更换推进按钮粒度不影响随机结果或对手进度。

# 旅居之魂：长夜归灯与沉钟修道院

2026-10-23。本轮延续 `/game/night-rain` 的相连世界，加入标题影像、新档序章、第四章与渲染优化。没有提交、推送或部署。

## 入口与关卡

完成天镜原后，从终点北侧垂星钟闸继续。旧存档按世界版本 13 迁移，仅追加七名新敌人，保留原有状态、物品、战败记录与路线。

关卡以“看得见目的地，先下降再回到上层”为主线：垂星长阶 → 沉钟眺台 → 西侧听雨阶 → 淹钟下库 → 提钟长阶 → 悬钟横廊 → 礼拜堂 → 晨雨放灯台。下库松开止水闩后水位下降，礼拜堂可开启；西侧抄经室提供额外补给和止鸣绳，东侧高廊有从内侧开启的回环近门。三处雨灯支持休息与已点亮地点之间的旅行。

新区域包含 15 个有高度的地面、三道门、12 个交互点、六名普通敌人与原创首领“无声钟守 · 余响”。首领的落槌可弹反、低扫要跳过；钟波在第一阶段连响两次，第二阶段三次。抄经室的止鸣绳只压住第三响，不免除其余战斗。击败后敲响晨钟进入第四章结尾，420 夜市钱仅发放一次，演出后可继续探索。

美术采用青绿玄武岩、沉水铜钟、悬链、三段拱廊和暖金晨光；远处可见钟体与礼拜堂，近处有止水绞盘、抄经书、路签和归灯。结尾使用固定全景，减少动态效果设置保留静止构图。

## 标题与新档序章

两段原创建模风格的 AI 影像分别为约 8 秒标题入场、18 秒新档 OP，均含生成的环境音轨。标题先展示静音影像，点击“重播入场 · 启声”播放完整入场；新档在序章结束或跳过之后才建立新存档，继续旧档直接进入游戏。

影像读取游戏静音/音量设置，播放时抑制游戏配乐、效果和陪伴语音。支持 Esc、跳过、手动播放、失焦暂停、减少动态效果以及损坏/加载失败回退。退出后卸载视频来源，游戏内没有残留视频元素。标题及影像期间停止连续 3D 渲染。

来源与完整 prompt、节点/提交/成片身份、原件和网页版本 SHA256、编码与字节数见 `night-rain-cinema-job.json`。两次任务均成功，未重复提交。预算 1000 积分，两次提交报价上限合计 468（144 + 324），最终净结算未审计。网页视频总计 4,604,321 字节，H.264 720p / AAC，保留环境声音字幕。原件与抽帧已目检，离线声音峰值分别为 -6.9 / -4.6 dBFS；没有做人工听辨评价。

## 性能改动与边界

`StaticDistrict` 将旧城及修道院不动的美术按 24 米空间块和材质合并，保留纹理、透明物体、灯光与动态交互。合并后的顶点保存原有线性色彩，原模型停止每帧矩阵更新；卸载时释放新增合并资源。当前调用都位于世界原点，若未来放入带变换的父节点，需要先转换到父节点局部坐标。

远处敌人超过 58 米切换为三网格剪影，回到 48 米内恢复完整模型，用滞回避免临界点反复切换；150 米外隐藏远景剪影。近战模型与判定保持完整。`window.nightRainRender()` 提供只读 draw call、三角形、几何体、纹理与帧时间，采样不遍历场景。

同机安装版 Chrome、1440×900、预热 2.5 秒后采样 5 秒：

| 旧城固定视角 | 优化前开发版 | 优化后开发版 | 最终生产版 |
| --- | ---: | ---: | ---: |
| 绘制调用（最高） | 4694 | 2116 | 2116 |
| 三角形（最高） | 489212 | 424384 | 424384 |
| 几何体 | 6326 | 2863 | 2863 |
| RAF 平均帧率 | 31.23 | 49.95 | 73.65 |
| P95 帧间隔 | 39.9ms | 25.9ms | 19.2ms |

旧城绘制调用减少约 55%，几何体减少约 55%。开发与生产的运行开销不同，不能把 31.23 → 73.65 的全部变化都归因于渲染改动。最终生产版天镜原约 153.5、修道院移动约 154.3、首领防御场景约 154.6 RAF FPS；390px 修道院约 143.4，P95 12.7ms。六组各 5 秒采样均没有超过 33.5ms 的帧。天镜原的调用从 262 增至 320，包含新增修道院远景及远处敌人剪影，不能宣称所有区域 draw call 都下降。

桌面 Chrome 的窄屏窗口只验证布局与该机器的渲染表现，不代表实体手机、Safari 或低端显卡的帧率。无上限的浏览器 RAF 采样可超过屏幕刷新率，不能当成显示器实际帧数。短窗口也不代表长时间游玩的最差情况。

额外通过 `scripts/verify-night-rain-render-recovery.cjs` 连续三次真实 WebGL context loss 与“重新载入 3D 画面”。每次保留位置和进度、只有一个画布、没有视频残留。GC 后 JS 堆从初始约 102.1MB 到第三轮约 97.5MB；几何体从初始 2862 到第三轮 2175，纹理 197 → 182，未出现随重建单调累积。这里只覆盖三次恢复，不等于长期内存泄漏证明。

- `scripts/verify-night-rain-bell.cjs`：区域构图、三连波、结束画面、390/320px 与地图、减少动态效果。

## 标题入场与待机循环修正（2026-10-23）

用户反馈本地标题开头卡顿、随后静止。旧生产包实测首屏构建3D场景形成约10.9秒主线程长任务，约8秒标题片在主线程恢复时已经结束；媒体已完整缓冲且播放统计无掉帧，不能归因为下载带宽。旧背景没有循环或结束后切换逻辑，因此永久停在尾帧。

现改为8秒入场自然结束后，淡入独立的4秒雨夜待机循环。复用既有片尾6–8秒，光流补帧放慢并以1秒溶接连接首尾，1280×720/24fps、无声、约800KB，无新增生成费用。预载但不同时播放两个视频；切后台/减少动态暂停，重播入场和进入游戏卸载背景媒体。手动带声音的入场演出与新档OP保持独立。

标题和OP期间不创建3D画布，实际进入游戏后才构建场景；加载时显示提示并冻结游戏步进。视频不再在JSX和effect里重复指定src，避免启动时重置加载。开发修正版首次playing约0.56秒，未再出现秒级长任务，循环两次无掉帧；性能结论以同机局部样本为限。生产验证数据见tmp/night-title-stutter/production/report.json，完整媒体回归和测试存档回归位于同目录下的cinema-production与test-saves-production。当前4127生产包改为.next-night-title-loop-release。

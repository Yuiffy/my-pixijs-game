## 可复用的经验

- 先修状态与估值语义。卖掉的棋子、候补、重复件收集价值、纯经济羁绊不能直接当作当前上场战力；开战前发现败局也必须能恢复正常运营。
- Node 与 Chrome 必须分开验收。即使初始快照相同，数秒后的战斗轨迹也可能分歧；最终以安装版 Chrome 和实际打包 Worker 为准。
- 预测准确率不等于整局收益。静态表留出准确率约 80.5%，仍未带来达到门槛的整局提升；开发集小样本收益不能代替独立两组对照。
- 区分战后收入与开战留钱。诊断筹资必须记录实际开战时刻，不能把战后金币直接归因为 AI 不花钱。
- 环境配置、规则、动作语义和运行时都要锁定。网页审计、interactiveRuntime、60Hz 正式战斗／20Hz 预演以及规则指纹必须一致；改变后不混用旧检查点与报告。
- 评测应逐局原子落盘，比较器拒绝错误、缺局、重复种子和运行时不匹配；分片合并必须覆盖完整指定范围。失败候选、部分报告和不确定性都保留。
- 轻量规则修复可独立评估；MuZero 本轮只是随机初始化的回合运营元控制器，没有从零学会全部战斗。现有样本未证明学习策略能稳定增强四档，继续扩大训练需要另行授权。

## 实验范围

依据 [MuZero 原论文](https://arxiv.org/abs/1911.08265)，实现 observation → representation、latent + action → dynamics/reward、latent → policy/value，使用单人折扣 PUCT 搜索和多步展开训练。网络随机初始化，不用战斗标签或预训练元控制器。搜索树只能调用学到的模型，不能调用真实游戏引擎或读取未来商店。真实引擎只在执行所选动作后提供真实下一状态及奖励。

这是一轮一次动作的**运营元控制器**：正常／提早升本／存钱／收窄刷新追星／花存款补强。具体买棋、升星、布阵仍由现有各档托管执行，原有棋力模型也仍在；不是从零学会完整游戏、也不宣称复现论文规模。使用对手规则反馈训练的过程需要样本，“无预训练探索”并不等于零对局即可得到强策略。

每轮观察当前经济、血量、人口、协议天赋、库存、可见商店、当前敌方组成与倍率、托管档位，不含随机数状态、种子或未来商店／敌方。正式战斗60Hz，现有档位内部预演20Hz，学习器不增加各档候选、战斗预演、未来信息或操作延迟。离线搜索开销不进入网页；只有通过整局对照的轻量策略或蒸馏结果才可接入。

奖励为每胜0.1、每损失一点生命扣0.025；死亡／16战Boss失败扣0.2，到实验上限仍存活加0.2。第16战失败即使剩余生命也必须结束，通关指标记录第16战获胜，另记录是否活到32战；二者不能混为一谈。奖励仅用于探索，最终验收比较真实胜场、通关和早期失败。

## 晋级要求

实验结果不等于可发布结果。正式接入前必须在四个可见档位（新手／老手／长考／看穿）都取得独立种子成对整局证据：胜场改善、通关不系统回退，并报告配对差值和不确定性。先开发对照，再冻结候选进行独立验收；不能反复按同一验收集调参。旧版隐藏go路径保留其能力边界并做回归，不能把它当作可见第五档更改默认。

在选出候选前预定实际验收口径：每档32战上限，两个未参与训练／选型的种子组各32局；每组平均胜场差均为正，合并平均至少增加0.25胜，合并通关局数不减少，8战及以前结束的局数最多增加1局。配对bootstrap报告95%区间及正差比例，正差比例至少80%；这不是95%显著性保证。若小幅效果的不确定性仍大，可增加新种子样本，但不能降低口径或按验收失败种子调参。默认／计算与信息预算保持原值。当前开发样本8局只作选型，不能通过此验收。

通过后按仓库要求定向ESLint、规则测试、完整check后顺序build，安装版静音Chrome验证真实Worker与设置／战斗／结算。未满足各档证据前不宣称目标完成，不推送未验收的MuZero模型或策略。

## 运行记录与实验修正

第一版128局与随后四档64局已完成，数据／权重留在`tmp/muzero/explore-1`和`explore-all`。第一版无预训练搜索没有取得四档共同收益。固定集中项目在八局开发集看起来有利，扩大至86100起32局后，新手平均胜场下降0.25、通关少2局，老手也未改善平均胜场；该固定规则不晋级。第一个小树教师一致率仅60%，长考开发集回退；减少无收益刷新单项也回退，均不采用。开发报告、明确拒绝原因和中止的部分对照留在`tmp/muzero/`，不把部分结果当作整组完成。

进一步修正MuZero训练的终局处理：采样真正的终局观测并训练零未来价值；展开越过终局时，任意动作进入奖励／价值均为零的吸收状态。已有回放可用`refine-autochess-muzero.py`重新训练，无需重玩或更改游戏规则。人工单步奖励模型验证单人搜索方向，真实环境重置确定性／正常关闭、16战Boss失败终止以及终局任意动作不产生虚构收益均有回归覆盖。增加持续随机探索，避免只靠早期少量样本固定偏好。

第一版经济动作发现一个设计缺口：`goldReserve`在风险参数为零时优先保护锚定利息，单独降低reserveCap／woundedReserve经常不会释放存款。`economy-v2`明确让“补强”最多动用4个利息档位的存款，“存钱”保护原利息；正常动作完整恢复原行为，不增加模型／战斗／信息预算。宏动作测试直接证明旧设定无效、修改后能动用存款并可恢复，并检查四档预算未变。这是实验动作修正，尚未接入正式游戏。动作语义变化产生新指纹，第二版从随机权重重新训练，绝不混用旧环境回放。第二版继续使用冻结的0c9f7bd运行源码；并行的保存UI和后台时钟修改保留在主目录，不进入本轮对照。

另外，整局报告的gold是战后收入到账后的金币，不能直接视为开战时留存。专项快照`inspect-novice-86125.json`确认该失败Boss局实际开战留21金、保留利息线20金，战后43金；没有把43金当作错误筹资证据。诊断在实际对局完成后使用独立快照，避免额外评估改变原决策。

第二版85400起128局训练已完成，按状态搜索的八局开发对照仍未改善老手平均胜场（12.875→12.25），不晋级。新手平均相同，长考平均与通关相同；因已不能满足四档要求，停止其剩余昂贵看穿对照，不把部分报告当完整证据。V2 normal动作与原参考八局逐回合轨迹完全相同。

验证配置进一步校正：早期实验关闭了网页开战前审计且没有启用interactiveRuntime，高档结果仅代表该离线配置，不能直接推广至实际Worker。当前环境与网页统一使用liveBattleAudit=true、interactiveRuntime=true，仍为60Hz战斗／20Hz预演且不增加候选预算。这改变环境指纹；旧检查点保留于冻结环境，不能直接在新环境评估或继续训练。新的真实配置参考为0c9f7bd运行源码＋e619e74桥接时钟修复，开发种子86200起，任何发布候选须在此配置重新验收。

## Chrome 运行环境复核

进一步逐字段核对发现：同一份战斗初始快照在 Node 与安装版 Chrome 中推进，约三秒后轨迹出现分歧，并会改变天赋选择及后续运营。其具体数值原因尚未定位。因此 Node 整局结果只证明 Node 中的效果，不能替代网页验收，也不能将 Node 单局翻胜当作 Chrome 的翻胜证据。

`scripts/evaluate-autochess-chrome.cjs` 将指定冻结目录的 TypeScript／JSON 依赖转译后装入安装版 Chrome Worker；无渲染、无音频，使用网页相同的现代档位、平衡风格、20Hz 内部预演、60Hz 正式战斗及开战审计。记录 Chrome 版本、源文件及评估驱动指纹，逐局原子写入报告，避免中断时覆盖上一份完整 JSON。实际 Next 打包 Worker 的 86200 长考路线已交叉核对：Chrome 中 16 战失败、开战留 20 金；此前 Node 中获胜／留 6 金的样例不再作为网页效果证明。

```powershell
node scripts/evaluate-autochess-chrome.cjs --source-root tmp/muzero/live-reference --runs 32 --seed 89000 --level deep --output tmp/muzero/chrome-reference-deep.json
```

比较工具拒绝不同运行环境的配对，以及跨组运行环境变化。Chrome 的候选依旧执行上面的两组独立验收门槛。中断前的部分报告不算完成；恢复时使用同一冻结源与相同种子重新运行，保留旧报告。

当前静态单位估值候选来自当前规则重新标注的 9,726 个标准化公开战斗场景，旧缓存缺少原始 UID／敌方站位，不能声称精确重放原战斗。训练器拒绝混用规则指纹或非 60Hz 标签，单位值相对费用基准限制在 ±50%，保留输入及训练器 SHA256。只使用训练数据拟合，完整游戏验收种子不参加拟合。

新手全局套用估值＋终局目标、老手去掉理财羁绊战力分均在独立验收失败，已从正式源码撤回。新候选只将静态战斗值用于新手／老手选上场阵容，购买／经济沿用原判断，不增加候选或模拟；开发后冻结再以新种子 89200／89300 验收。所有当前实验仍未提交，不能宣称四档稳定增强已完成。

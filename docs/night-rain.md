# 岁己 · 雨夜寻味

## 原始目标与完成边界

> 制作一个仿只狼、黑魂、老头环的3d动作rpg游戏，注重地图设计和战斗体验。我们先做箱庭第一关（类似洛斯里克高墙？），以便积累经验后面再做开放世界。游戏背景就是岁己买了笔记本电脑去泰国旅居吧，泰国很危险所以有一些敌人。第一幕就是直播完了出去找好吃的吧。

交付范围是可从头到尾游玩的**第三人称 3D 动作 RPG 第一关**。地图要有高差、可辨认的地标、埋伏与回路；战斗要能通过观察、空间判断、资源管理和练习提高胜率。只狼、黑魂和艾尔登法环提供设计参考，不复制它们的素材或原关卡。后续开放世界是迭代方向，本关要积累可复用的战斗与地图经验。

开场是岁己在泰国旅居的旅馆里结束直播，合上新买的笔记本，出门寻找夜宵；结尾要真正抵达摊位并吃到饭。敌人与封街冲突属于本关虚构剧情。

此文档记录目标、实现与验收证据。2026-09-26 已完成脚本可通关的第一幕与宝宝模式；自动驾驶通关证明规则和路线可完成，操作手感、初见可读性与难度仍需玩家试玩反馈。

## 第一关空间设计

坐标采用米：`+x` 向东、`+z` 向南、`+y` 向上。地表、碰撞、地标和出生点的统一来源为 `src/components/nightRain/world.ts`。

```text
旅馆房间（6m，笔记本）
        │ 旅馆外梯
        ▼
    雨灯中庭 ── 晾衣暗巷 ── 旧城高阶（0→6m）
        ▲                          │
        │ 单向开门                 ▼
    运河侧廊                  金塔屋脊（护符／便签）
        │                          │ 夜市长阶（6→0m）
        └────────── 封街夜市 ──────┘
                    │ 首领
                    ▼
                 夜宵摊位
```

| 区段 | 设计职责 | 要在实机中证明的行为 |
| --- | --- | --- |
| 旅馆与外梯 | 用笔记本和城市视野交代下播出门，安全学习镜头与移动 | 玩家能自己下楼；楼梯与地面交接不断步、不穿墙、不被镜头遮住 |
| 雨灯中庭 | 初次遭遇与明确的复活、补给中心 | 读懂敌人起手；战斗后能休息；死亡回到已点亮的雨灯 |
| 晾衣暗巷 | 障碍、转角与钱袋支线 | 转角敌人可被观察和拉开；拾取具有实际奖励 |
| 旧城高阶 | 在高差与较窄空间重新应用战斗动作 | 玩家和伏兵脚下高度正确；攻击与镜头不穿楼层 |
| 金塔屋脊 | 高处辨认回路、护符奖励与刀客决斗 | 护符确实改变玩家能力；屋脊宽度允许走位；可辨认夜市方向 |
| 夜市长阶与封街夜市 | 从狭窄路径进入开阔首领场，形成节奏变化 | 下阶顺畅；首领有可读招式及可反击窗口；胜利会解除通行条件 |
| 运河侧廊与中庭侧门 | 首次从远端开启捷径，缩短后续跑图 | 关闭时不能从中庭穿过；开启后双向步行连通，休息／死亡／刷新后仍开启 |
| 夜宵摊位 | 回应开场动机，完成第一幕 | 首领存活时不能跳过关卡；击败后可主动点餐并进入结尾，刷新可恢复 |

2026-09-12 几何审查：使用源码实际 `heightAt`／`canOccupy`，在 0.25 米四向网格上从出生点搜索。关闭侧门时有 15,903 个可达采样点，全部七个地标与六个敌人出生点均可达；所有敌人声明高度与地表一致。中庭出生点到侧门拉杆的网格距离从关门时 109.25 米降至开门后 31.25 米，到饭摊从 85.25 米降至 73.25 米。该证据只证明当前离散碰撞网格的连接性，不能代替玩家半径、动作位移、敌人阻挡、实际镜头与整段路线测试。

地图审查关注：旅馆外梯在 `x=8..12,z=0..10` 与中庭投影重叠，地表查询选择较高的楼梯。美术必须忠实显示这个坡道，侧边高度突变处需要可理解的围挡；不能把这一片画成平地。楼梯顶端与屋脊边界也需要实际正反方向试走。

## 战斗与 RPG 验收

默认操作：WASD 移动，捕获鼠标后直接转镜头，左键轻击、右键重击、中键或 Q 锁定，Space 闪避、F 弹反、R 补给、E 交互，Alt 临时显示光标，Esc 暂停，M 地图。支持标准手柄；键位、资料依据与虚拟测试约定详见 [动作游戏输入](night-rain-controls.md)。移动端要有真实触控移动、镜头和动作按钮，并能同时移动与出招。

| 要求 | 当前证据与边界 |
| --- | --- |
| 第三人称 3D 场景与相机 | 系统 Chrome 实际拖动改变 yaw；台阶、屋脊、回廊、望台与夜市完整路线截图逐张目检；相机对静态城市场景做遮挡回缩 |
| 键盘、触屏与动作 | controls 专项真实按键／触摸验证移动、轻重击、闪避、弹反与交互；assistance 专项验证双指同时移动与转镜头、触屏按下即时出招 |
| 战斗规则与敌人差异 | 规则测试覆盖前摇命中、收招、体力、正面弹反成功与过早／背向失败、闪避无敌及恢复受伤、墙体／高差阻挡、首领第二阶段；整关合法输入击败全部敌人。尚未做多人初见难度研究 |
| 首领与章节完成 | journey 全程只读状态并提交合法输入，不改生命或位置；击败首领、点餐、进入结尾及刷新恢复均通过 |
| 休息、升级与探索奖励 | journey 实际收集两处宝箱、钱袋、护符及便签，回雨灯整备；规则测试覆盖恢复、普通敌人重置及奖励只领取一次 |
| 死亡与损失找回 | 规则测试通过真实伤害死亡、显式重生、合法路径返回与找回损失；本轮浏览器截图未单独重复死亡场景 |
| 捷径与回路 | journey 步行回廊小环、从夜市侧开门并返回中庭再赴夜市；规则测试和寻路测试交叉验证开关门连接与持久状态 |
| 持久化与容错 | controls 刷新存档，journey 结尾刷新，assistance 坏档／拒绝存储与设置持久化通过；规则验证战斗档、重复领取防护 |
| 宝宝模式 | 六项精灵测试覆盖共享碰撞寻路、跟随等待、危险停留、分级／遗漏提示及关闭暂停失效；journey 实际跟随精灵到雨灯并响应遗漏提示请求钱袋带路 |
| 字幕与可选语音 | assistance 记录中文 SpeechSynthesis 真实 start 事件与系统中文声线；两种外观、关闭模式及刷新设置通过。音色取决于设备 |
| 布局与运行 | 桌面、390px、320px 与横屏截图通过尺寸／溢出／像素检查，27 张最终图均已打开目检；三个专项 errors 为空，暂停、失焦、焦点、全屏、渲染重载通过 |
| 仓库门禁 | 隔离验证目录顺序通过 pnpm run check 与 pnpm run build（51/51 页，保留 ESLint／类型检查）；本轮全部游戏源码、路由、demos 和 package.json 与主工作区逐文件 SHA256 一致，仅既有 overworldRpg unused 警告 |

## 验证方法与产物

浏览器入口为 `/game/night-rain`。本仓库专项脚本 `scripts/verify-night-rain.cjs` 使用安装的 Chrome channel，先确认目标 URL 返回 200，再启动浏览器。截图使用 `page.screenshot({ fullPage: true })`，交给 `scripts/lib/autochess-screenshot.cjs` 的 `inspectPng` 拒绝纯色、近黑或透明捕获；每张用作验收证据的截图还必须打开目检。GPU 捕获异常时，以同一实例文本状态、画布尺寸、DOM 和错误日志定位，先检查捕获路径；当前自动化按用户要求只用隐藏系统 Chrome 和虚拟 Pointer Lock，不启动可见窗口或真实捕获系统鼠标。

浏览器只通过实际 UI 或公开输入钩子驱动玩家：`window.nightRain.input(action)`、`advance(ms)`；状态只读 `getState()` 与 `window.render_game_to_text()`。完整路线脚本不得直接改位置、生命、首领生命、奖励或关卡标记。它可以据只读敌人时序选择合法输入，但自动驾驶通关仍只证明规则与路径可完成，不能替代对操作手感的人工判断。

最终证据为 `tmp/night-rain-final-controls/`（7 图）、`tmp/night-rain-final-journey/`（15 图）与 `tmp/night-rain-final-assistance/`（5 图），均含状态、像素检查与 report。生产版另见 `tmp/night-rain-production/`。遗漏提示由状态断言验证，截图可能已过字幕显示时限，不将该截图单独当作字幕证据。

## 后续经验记录

第一关验证后再据实记录：初见玩家如何辨认目标、最常迷路的岔口、首领初次胜利所需尝试、弹反与闪避是否均有价值、补给消耗和捷径节省的时间。开放世界扩展应使用这些结果决定据点间距离、敌人密度与战斗持续时间，不能用扩大地面面积代替关卡设计。

## 2026-09-26 · 箱庭第一幕与随身精灵

本轮目标：完成可玩的雨夜魂系箱庭第一关；宝宝模式带来漂浮的饼干岁／獭獭栞、由浅到深的遗漏和接近提示、字幕与可选系统 TTS，并可请求精灵直接带路。参考魂系的层次、回望、岔路回报与捷径节奏，不复制原作关卡。

视觉方向：雨蓝色旧城、暖金灯火、可辨认的金塔与屋顶天际线。开始界面用整屏真实场景承载标题；游玩时只保留生命体力、瞬时交互和精灵字幕。场景雨丝、精灵浮动和开箱动作承担动效，地图与长说明折叠在菜单中。

关卡结构：
- 主路径从六米高旅馆眺望目标，下外梯进入中庭，穿晾衣暗巷，在高阶上逐渐抬高视野，经过屋脊决斗后看见夜市首领与食堂。
- 铃兰回廊在高阶半腰形成真实岔路；宝箱奖励 35 夜市钱，矮阶接回中庭，构成较短探索环。玩家也可从中庭反向探索，先拿资源，再从高阶接主路。
- 金塔望台是屋脊上的可选支路，宝箱与高处观察提供双重回报。屋脊便签解释夜市和运河侧廊关系。
- 夜市东侧可在挑战首领前绕到侧门背面。开门后能回中庭补给、整备，后续重试不用再爬屋脊。守门人与两阶段铁伞分别检查窄路节奏和开阔空间判断。
- 胜利后必须主动向摊位点餐，结束下播觅食的第一幕。

宝宝模式：
- 开始和暂停时都能开关，不强制改变战斗伤害；两种原创程序化 3D 精灵造型可切换，设置保存在本机。
- 进入发现附近先给柔和暗示，经过后走远提醒可能遗漏，靠近目标时给出更明确的字幕。提示有冷却，拾取后不再重复提醒。停留过久会提示可求助；战斗时优先说明体力、回血和不可弹反招式。
- 按 C 或界面精灵按钮交谈。“直接带我去”优先响应刚才提示的发现，也可指定主线、宝箱、雨灯或捷径。
- 带路使用与玩家共享地表、半径、墙体和门状态的寻路；精灵走楼梯、等待落后玩家、遇敌停下，不移动玩家、不替玩家战斗或领取物品。
- 可选语音使用浏览器 SpeechSynthesis 的中文系统声线；音色由设备决定，不仿角色声优。语音失败时保留字幕，暂停、关闭宝宝模式和离开页面会取消播报。
- 宝宝模式还会在临近命中窗口时显示弹反／闪避提示；基础模式保留原有攻击动作和地面预警。

源码：NightRain.tsx 负责页面与输入，engine.ts 负责纯规则，world.ts 统一几何，companion.ts 负责提示与寻路，WorldView.tsx / CompanionView.tsx 负责显示。

入口：`/game/night-rain`，实验室 `/demos` 新增游戏卡片。本地开发默认 `http://127.0.0.1:3870/game/night-rain`。

验证命令：`pnpm night:test`，`pnpm night:verify`。浏览器三个专项依次覆盖输入与响应布局、合法输入完整第一幕、精灵与异常恢复。全部使用系统 Chrome、full-page 截图和非黑检查，不使用已知不可靠的 SwiftShader Canvas 捕获。

最终 21 项规则／精灵测试通过，三个 Chrome 专项与顺序 check/build 通过。公开预览图来自最终实机截图。当前为可试玩的几何美术第一幕，2026-09-26 按用户要求纳入 master 发布流程；后续重点是玩家初见路线、敌人读招与战斗手感反馈，不能等同于大型商业魂游的内容规模和打磨程度。

# 虚境归途 · 版本计划与验收

## 原始目标

制作一个类似《金庸群侠传 1》的俯视视角 2D 开放世界 RPG。玩家是穿越进虚拟世界的管人粉丝，以饼干岁为主角，在各地结识并招募岁己、栞栞等主播，组成队伍、培养战力、逐步挑战更强的对手，最终打败最终 Boss，回到现实世界。

战斗采用自动战斗，可选手动控制主角；角色美术复用现有自走棋素材。探索、遇见同伴、做出队伍选择和成长后攻克强敌应共同构成体验，不能用连续战斗菜单替代开放世界。

本项目按版本持续迭代。首版通关只证明最小完整旅程成立，不代表开放世界的内容深度、长期成长和叙事完成度已经达到最终目标。

## v0.1 · 可以走到结局的第一段旅程

目标：从穿越开场开始，在可自由行走的连续地图上招募队友，挑战区域敌人，获得成长与通行条件，击败终敌并看到返回现实的结局。

- 俯视地图包含村落、道路、林地、水域与区域地标；相机跟随玩家，地形实际阻挡移动。
- 主角采用饼干岁形象；岁己、栞栞等同伴拥有各自定位与技能，通过地图上的会面或区域事件加入队伍。
- 世界中可以选择探索顺序，包含篝火、宝箱、普通战斗与区域首领；招募、补给、等级、资源和终点条件相互关联。
- 自动战斗可观察队伍技能与血量变化；主角可选手动移动与技能。上阵人数限制产生组队选择。
- 胜利给予资源和经验，失败允许恢复和重新尝试，不阻断整个存档。
- 支持本地保存与继续旅程；损坏存档安全降级，中途战斗恢复到可操作状态。
- 桌面键盘、地图点击和手机触控都能完成探索与对话；小屏可阅读目标与战斗结果。

验收以实现和实际运行证据为准：规则测试必须通过合法移动、交互、招募、营地与战斗完成一次完整旅程，不为通关直接写入金币、等级或队员。浏览器需验证实际输入、画面、文本状态、存档恢复、失败重试与最终结局，并逐张检查采用的截图。实现中项目保持待验收，避免将路线图当作已实现清单。

当前规则实现包含 6 个区域、主角与 4 位可招募伙伴、4 处驿站、4 个补给宝箱、9 场遭遇战（含 3 位碎片首领与最终 Boss）。四人上阵、全队等级与武器成长、免费休息、恢复药、已发现驿站往返、三枚碎片解锁终战和返回现实均已有对应规则。战斗中主角可手控移动并按空格施放技能，伙伴仍自动作战；默认全队自动。

2026-09-12：10 项规则测试通过，覆盖独立地图 BFS、实际跟随点击寻路抵达全部地标、远距与任务条件限制、一次性宝箱和已发现驿站旅行、合法行动完成全旅程、失败恢复重试、战斗中存档恢复、结局读档、四人上阵限制、真实战斗受伤后用药、暂停与手控、坏存档处理。该记录证明规则层闭环；浏览器视觉、触控与构建验收应另以本轮实际报告为准。

## v0.2 · 让地图上的地方值得记住

目标：从有地标的开放地图扩展到值得回访的世界，而不是只延长地图距离。

- 增加村屋、客栈、工坊、遗迹等可进入的室内与独立地点，加入地方人物和环境叙事。
- 为岁己、栞栞等队友增加个人支线、相遇前的线索、队内对话与关系变化。
- 增加具有条件、后果和后续反馈的任务选择；线索、捷径、区域事件影响探索顺序。
- 加入旅行日志、已知地点索引与支线追踪，使玩家能理解下一步而保留自由探索。
- 补充可选强敌与隐藏奖励，避免只依靠主线等级门槛引导路线。

本版已进入实现与验收阶段。当前计划落地回音客栈、书院、工坊与遗迹四处室内，以及岁己的灯火支线和栞栞的书信支线。两条支线都应具有相遇前的线索、招募后的前置条件、互斥的结局选择、实际生效的队伍收益、回访对白与终章反馈；遗迹另有可选守卫和解锁捷径。

室内应有自己的碰撞、进出位置和存档恢复；旧版存档应保留已有金币、成长、队伍和已到达的结局，迁移后新增剧情从未开始状态继续。上述条目仍以规则与浏览器实际证据逐项验收，不因新增文件或界面已经出现就视为完成。

本版的两条个人支线采用以下设计；每条只能获得一种祝福，选择后应在回访对白、旅记和返乡尾声中留下对应结果。

| 支线 | 探索经过 | 选择与队伍影响 |
| --- | --- | --- |
| 岁己 · 留一盏灯 | 客栈听旧灯的故事 → 晚风泽寻回灯芯 → 回到掌柜身边作决定 | 留灯守候：治疗提高 22%；携灯同行：气血上限增加 32 |
| 栞栞 · 未写完的信 | 书院接过空信封 → 观星台读碑记 → 让执信守望者安息 → 带信回书院 | 珍藏在书院：防御增加 3；念给来往旅人：攻击增加 4 |

听钟铁铺中的人物与拓片提供旧道线索。执信守望者属于可选内容，不占主线三枚碎片；胜利后，观星台至书院的旧道应成为实际可用的路线。提前到访室内也能读到人物线索，但不能跳过招募和任务前置直接领取祝福。

## v0.3 · 让自动战斗中的选择更有分量

目标：把当前队伍组合深化为可理解、可试验、有不同解法的自动战斗策略。

- 战前布阵、前后排、目标选择与技能时机形成稳定规则，并让战场反馈解释胜负原因。
- 引入适量羁绊、装备与构筑选择；不同同伴应提供可替代但不等同的战术价值。
- 首领拥有可辨识的阶段或机制，允许通过换队、阵型、养成或手动操作解决。
- 加入战斗统计和战术提示，减少玩家只能盲目升级后重试的情况。
- 覆盖多种合法阵容的全程回归，限制无限治疗、无敌拖延和经济循环等失衡策略。

本版在世界内容初步成形后实施，目前属于计划。

## v1.0 · 完整的归途

目标：完成有充分探索、人物弧线、战力成长和情绪收束的长篇旅程。

- 扩充多个可自由往返的区域、主线章节与可选支线，形成清楚的强敌递进。
- 让同伴经历和玩家决定参与终章；最终 Boss 和返回现实的结局回收穿越的伏笔。
- 完成画面层次、角色动画、音效、音乐、操作反馈、无障碍与移动端体验打磨。
- 制定存档迁移策略，对完整长线存档、不同招募顺序和异常中断进行回归。
- 通过真人试玩检验探索动机、战斗可读性、策略选择与节奏，再调整内容密度和数值。

v1.0 是否完成必须逐项审查原始目标和本版交付内容；当前不能由首版通关、测试数量或构建成功推定完成。

## 实现与验证入口

- 游戏源码：`src/components/overworldRpg/`。
- 规则回归：`node --test scripts/tests/overworld-rpg.test.mjs`。
- 规则测试只证明其覆盖到的地图可达性、战斗、成长、存档和流程；美术、交互可读性及手机可用性还需浏览器证据。
- WebGL 视觉测试按仓库约定使用安装的 Chrome 通道和页面截图，结合 `window.render_game_to_text()`、DOM、画布尺寸及控制台错误。拒绝全黑、透明或单色的异常捕获；所有采用的截图须打开目检。
- 源码提交前顺序运行 `pnpm run check`、`pnpm run build`，保留 Next.js 构建时 ESLint，不并行运行 TypeScript 检查和 Next.js 构建。

## 2026-09-12 · v0.1 验收结果

首个完整可玩版本已实现，入口 `/game/rpg`，本机开发服务 `http://127.0.0.1:3860/game/rpg`。

- 16 张最终完整页面截图已逐张打开检查，覆盖标题、对话、地图、队伍、普通/区域/最终战、结局、390px 真实触屏、320px 小屏、2560px 大屏、存储不可写与败退。像素检查、DOM、画布尺寸、文本状态互相核对。

# 裂隙阵线 · 多人模式

入口 `/game/autochess` 默认进入成熟的传统本地挑战。顶部「多人模式beta」前往 `?mode=multiplayer` 选择合作卫戍 / 多人混战；手机标题页也提供此入口。`?mode=classic` 和原有 `?seed=` 调试入口继续进入传统模式。

## 规则与交互

- **合作卫戍**：1–4 人，20 生命，守住 16 波。所有存活玩家各打一场相同种子的敌人波次。必须清空敌军才算守住，超时仍有敌人也算漏怪。守住者带存活棋子为一名漏怪者救援一次，救援继承剩余生命、能量和护盾，重置站位与场地临时目标；不复活阵亡棋子。每个漏怪者最多获得一轮救援，每支胜方队伍最多救援一人，多人漏怪时优先级逐轮轮换。救援清空则漏怪者不扣血，否则只按最终剩余敌人星级之和扣漏怪者的血；协助者不因救援失败扣血。无人可救时直接按漏怪结算。淘汰者观战，至少一人存活至第 16 波则小队共同胜利。
- **多人混战**：2–8 人，40 生命，准备阶段已知本轮对手与其上一轮锁定阵容。使用循环赛配对；存活人数变动后按存活席位重新配对。奇数人轮换一人打另一名存活玩家的复制幻象，本体不承担幻象战损失。实体对战只模拟一场，双方共享结果；败者损失胜方存活星级之和（至少 1）加每五轮递增的伤害。战斗时限按原引擎剩余战力裁定，完全相同时由配对左侧胜出。最后一名存活者获胜；第 40 轮强制按剩余生命结算，并列者共同获胜。
- 新模式统一以 10 金、一星海苔开局。沿用原版商店、人口、升本折扣、三合一、升星工坊、站位和羁绊；新模式不使用远征开局/局中天赋。每轮基础收入 7 + 原引擎利息（包含理财羁绊对利息的加成）+ 守住/取胜 1 + 已激活理财收入。AI 只使用自己的商店和实际金币。
- 本地为一名真人加 0–7 名 AI（合作最多三名 AI），自动保存与恢复。线上允许纯真人或混合 AI。房主调整模式、总人数、AI、60/90/120 秒备战、公开/私密；不能移除已入座真人。所有席位到齐后才能开局。
- 准备后锁定自己的操作，可取消准备。全员准备或到时直接同步开战；空阵可参战并按真实结果受罚。等最长防守结束后，若有救援则立即同时开始兜底，无额外开战倒数。所有战斗结束后展示 4.5 秒结算，自动进入下一轮或最终结果；无需战报确认，掉线不会无限阻塞房间。战斗提前结束后继续显示休整时间，胜方存活角色轻跳庆祝、残留特效自然淡出，等待期间画面保持活动。离开对局回大厅保留席位，原浏览器可恢复，淘汰后可看其他战线。等待中的客人可退席，房主可关闭房间。
- 棋盘点击棋子再点目标格移动/交换，支持自动布阵、备战席、卖出。对手阵容侦察仅展示上一轮，不暴露本轮商店、经济和调整。战斗中直接点玩家头像切换实时战况，以原 Phaser 角色、技能和效果播放，保留统计、详情和全屏；多人不提供独立暂停、倍速与快速结算。

## 联机架构

`multiplayer/match.ts` 复用 `AutoChessEngine`，将多人轮次与传统远征进度分离；本地与服务端使用同一个多人规则层。服务端按 60 Hz、24 秒战斗上限执行无画面/无事件日志模拟，返回战斗初态和统一结算。客户端根据统一时间线重现战斗，不提交胜负或单位数值；切换观战和重连按房间当前时间补算到对应帧。

`/api/autochess` 复用上船的 Neon `DATABASE_URL`。首次使用幂等创建独立 `autochess_rooms` 表，不影响上船房间。房间保存 JSON 状态与 revision；所有更新通过 revision 条件提交，防止重复购买/开战/结算。玩家操作另核对个人 revision：其他玩家同时操作引发的房间冲突，在个人状态未变时最多重试四次；重复提交同一个人的操作会被拒绝。无法合并的冲突返回最新状态，用户可再次操作。房间身份是随机 256 位令牌，数据库只存哈希；客户端仅收到自己的备战状态和上一轮公共情报。接口检查来源、JSON 类型、4 KB 请求大小、席位权限、轮次和操作参数。

浏览器约每 1.8 秒轮询；未变化时只回 revision 与服务端当前时间，减少大型回放数据传输。倒计时是持久化时间戳，由任一已认证的状态/操作请求推进，无常驻定时器要求。全部浏览器关闭期间不做无意义后台计算，下一次连接推进一个到期阶段。房间七天不活动过期。席位令牌存在本机 localStorage，不能跨浏览器自动认领。

Vercel 使用 Node.js runtime，单请求上限 30 秒。决策依据是实测，而非假设需要逐帧网络广播：本机首轮 16 轮基准，8 人混战最慢 156 ms/轮，4 人卫戍含救援最慢 324 ms/轮；这是本机 CPU 数据，不等同于生产冷启动、数据库与并发延迟。可用 `node scripts/benchmark-autochess-multiplayer.mjs` 重测。

补充满编压力测试：每人 10 个三星棋子，包含召唤与治疗阵容，7 人（含幻象）一轮 317 ms，8 人一轮 269 ms；每轮初始共 80 个参战单位，房间 JSON 约 255 KB。当前采用服务端统一裁决，不接受客户端上报胜负；客户端双算可作为未来诊断手段，但无法自行解决结果不一致或串通问题。尚未测量实际 Vercel 冷启动、线上并发与运行费用。

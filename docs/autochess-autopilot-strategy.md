# 自走棋托管策略与评测指南

## 当前方法

托管采用“分层规则 + 有界真实战斗推演”，而不是直接训练端到端模型：

1. 阶段状态机保证协议、整备、天赋、战斗和结算都能有限步完成。
2. 规则层负责生成少量合法候选，包括商店目标、升级、刷新、出售和阵容组合。
3. 真实战斗引擎负责比较候选，而不是只按费用或羁绊相加：协议预演前三战；阵容最多比较四个候选；天赋比较下一战结果。
4. 硬约束保护升级素材、二三星单位、目标阵容和人口上限，并限制刷新、出售和每回合操作次数。

这种组合能直接感知棋子自身数值、技能、射程、目标选择和站位结果。功能型单卡只要在真实战斗中改善结果，就可以胜过纸面费用更高的棋子；羁绊阈值只用于提出候选，不负责最终拍板。

## 为什么暂不训练小模型

目前没有足够的高质量真人轨迹，也没有稳定的版本化训练集。直接训练策略模型会把少量旧版本操作当成答案，并且很难解释满席卡住、错误出售或经济误判。当前真实引擎推演具备三个更重要的条件：确定性、可回归、规则变化后立即生效。

模型适合在积累数据后作为“候选评分器”，而不是直接控制游戏：

- 输入使用版本号、种子、回合、商店、金币、等级、阵容、站位、羁绊和最近战果。
- 目标先做真人选择排序或最终存活波次预测，不直接输出鼠标动作。
- 模型只重排规则层生成的合法候选，出售和移动仍经过硬约束。
- 每次晋级必须在固定种子、留出种子和真人轨迹回放上同时不回退。

## 协议、阵容与经济

协议选择会为每个候选运行三战完整托管。只有预演胜场严格更多时才推翻长期静态偏好；胜场相同沿用偏好，避免把稳扎稳打自带的核心生命误当成长期战力。

阵容搜索先生成费用/星级、角色、羁绊阈值和单卡替换候选，再选启发式最高的四组进入真实战斗推演。棋盘和候选席全满时，可把目标候选席棋子直接与场上非目标棋交换，避免反复选中后非法上阵。

经济采用保守门控。低血量、缺人口和立即合成时照常投入；只有至少两连胜、真实推演大幅领先且不会跨档付费刷新时才保留该次利息。候选席全满、正好差一金币升息时，最多出售一个不在目标阵容、不是升级素材的一星一费单卡。理财二档自动使用每四金币一档和二十利息上限。

## 固定基准

基准命令：

```bash
pnpm autochess:benchmark:autopilot -- --runs 24 --seed 73000 --battles 16 --output artifacts/autochess-autopilot-v022-final-24.json
```

`73000-73023`、前 16 战的当前结果：

| 版本 | 平均终止战 | 平均胜场 | 主线通关率 | 非法移动 | 最长选中停滞 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 修复前基线 | 9.75 | 5.58 | 0% | 0 | 0 |
| 阵容真实推演与安全出售 | 13.42 | 10.17 | 12.5% | 0 | 0 |
| 三战协议前瞻与谨慎经济 | 14.38 | 11.33 | 16.7% | 0 | 0 |

真人演示种子 `73042` 中，旧托管选择稳扎稳打并在第 7 战结束；三战前瞻改选流量续航，主线通关并到第 17 战。真人同种子到第 21 战，仍是后续优化目标。

## 轨迹与复现

- `autoChessAI.actions(200)` 返回本局结构化操作及操作前后状态。
- `render_game_to_text().recentActions` 返回最近 12 条操作。
- `window.autoChessLastRun` 在终局、组件卸载和同标签页刷新后保留上一局状态与最多 640 条操作。
- `--starter <id>` 可强制基准协议，用于比较同种子的开局分支。

评测至少同时观察终止战、胜场、通关率、最终核心、利息、非法移动和选中停滞。单个种子改善不能替代固定样本；任何策略实验若降低通关率或胜场，应撤回或缩小触发条件。

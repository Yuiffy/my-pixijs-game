# 自走棋棋子与羁绊设计指南

本文件记录自走棋角色、羁绊和技能的当前设计共识。改动数据前先阅读；当新的反馈推翻既有判断时，同步更新本文件，而不是只改配置。

## 核心目标

- 玩家应能从**棋子名、羁绊名和技能名**直接猜到大致效果。
- 角色首先是主播与社区梗的角色化，不是通用奇幻职业模板。
- 显示名称优先短、好记、像社区里真实会使用的称呼。
- 机制、技能描述与实际实现必须一致。

## 棋子命名

### 应该做

- 使用明确、短小的角色称呼或梗，例如「橙色兔子」「雅吨」「好笑姐姐」「邪恶外星人」「中单光一」。
- 只有在确实帮助理解时，才用「角色名·梗/动作」的形式，例如「弥月·浮游炮」。
- 让技能名直接说出动作或核心意象，例如「苹果派」「滑跪」「兔耳浮游炮」「外星光线」。

### 不应该做

- 不使用脱离社区语境的泛奇幻包装，如“巡林者、术士、潮汐卫、终幕护航、裂界”。
- 不使用无法看出效果的抽象组合词，如“协战引导、设备组、疾行直播间”。
- 不在面向玩家的 UI 显示原名/英文名/职业副标题。`UnitDefinition.title` 可以保留为内部兼容字段，但 UI 不应渲染它。

## 羁绊设计

- 名称尽量是简短的类别、关系或共同梗，例如「主持」「矮人」「骷髅兵」。
- 羁绊成员必须能解释为什么被归为同一组；没有共同点时不要硬凑。
- 每条羁绊应有独立的核心收益，避免两个羁绊提供近似效果。
  - 例：矮人使用闪避；骷髅兵使用高攻低甲，不能也做闪避。
- 文案必须说清楚作用对象、频率、上限和高阶额外收益。
- 高阶羁绊可以从“仅成员获益”扩展为“全队某类单位获益”，但不要造成难以追踪的叠加。

## 技能设计

- 技能名称、描述和 `gameEngine.ts` 中的实际效果需要一一对应。
- 不要描述未实现的效果，如“沿途伤害、嘲讽、隐身、减速”等。
- 一位角色最好有一个清晰的战斗句子：
  - 七海大鲨鱼：扑向密集敌群，范围伤害并眩晕。
  - 能能弄你：以低单发伤害进行高速多段射击。
  - 中单光一：滑跪切入，冲线控制并获得护盾。
- 伤害型技能应避免把低血收割、灼烧、护盾、位移等全部堆在同一个技能上；保留角色最核心的一到两个记忆点。
- 如果技能使用社区梗，不需要在描述里解释梗的来源；只需解释游戏效果。

## 新增或修改棋子的检查清单

1. 在 `gameData.ts` 更新棋子名、技能名、描述、羁绊、属性和商店注册。
2. 在 `gameEngine.ts` 更新相同 `UnitId` 的技能实际逻辑。
3. 确认技能描述没有超出实际实现，也没有遗漏关键效果。
4. 检查其羁绊是否与已有羁绊的效果重复。
5. 如果新增商店棋子，更新测试中的商店总数和角色断言。
6. 不在 UI 中展示 `title`；只展示棋子名、费用、属性、技能和羁绊。
7. 执行 `npm run autochess:test`；涉及 UI 时还应运行浏览器验证。

## 头像

- 普通主播头像仅在构图适合时使用。
- 一张含多套服装、文字或网页排版的设定图不宜直接作为棋子头像；应改用已审核的单人 Q 版头像。
- 新 Q 版头像需透明背景、正方形、居中，建议输出为 512×512 PNG。
- 生成候选图不应直接发布；先人工审核，再用项目脚本规范化处理。

# 潮夜格斗 · 接触判定与防御设计

Original prompt: 调研目前的格斗游戏如街霸6，完善我们的细节，比如受击body范围、攻击判定范围（可以用图像像素判断处理）。还有两人攻击撞上是否拼拳抵消，是否加入精确防御，是否能打回去敌人发的波等。

## 轮廓烘焙

`scripts/prepare-tidal-collisions.py` 读取三人的原皮 motion、combat、air WebP，共 168 个姿态。先取 alpha ≥128，再裁到人工校准的头躯、腿、攻击肢体区域；排除主要长发、帽饰和孤立碎点。8×8 源像素网格覆盖率达到 1/8 即保留，按同行连续段与纵向相同段合并矩形。当前最多 30 个受击矩形，分发 JSON 为 54,373 bytes；来源与区域坐标见 [碰撞审计](tidal-duel-collision-audit.json)。

这是根据 alpha 与人工区域校准的简化轮廓，包含网格近似；不是逐像素精确碰撞或自动语义分割。每套衣装共用角色原皮的判定，换装不改变对战平衡；原图不变，运行时不读取像素。

`animation.ts` 统一有效帧选择，`collision.ts` 使用相同脚底锚点 `[224,440]` 与 2 倍世界比例。普通肢体攻击的红框来自有效帧 alpha，另加 4 世界像素边缘容差。伸出肢体近端 55% 仍可被打，末端允许与另一攻击拼招。兼容字段 `attack` 是全部红框的外包围，真正接触逐个检查 `strikes`，不拿透明空隙填成整块攻击框。

投技是明确标定的抓取范围；升击/浮空招是经过身体上方的扫弧；超杀是能量范围。后三类使用 `grab` 或 `effect`，不把终点拳头冒充整条运动弧，也不参加普通肢体拼招。推挤仍采用独立 99×175 世界像素范围；无敌、倒地、起身和侧移规则先过滤接触。

实际身形决定是否接触：栞栞的站立高横踢会从完全蹲下的头部上方掠过，岁己和弥月较低的横踢仍能碰到蹲姿。横向空中掌/踢在高处通常可蹲躲，低空横踢也可能碰到蹲姿；下劈可向下击中。高度规则继续决定接触后怎样防御，不能仅凭招式标签认定一定命中。

## 相打与拼招

同一模拟 tick 在任何打击改变角色状态前，快照双方动作、位置、防御、反击、浮空和无敌状态。即使第一下已造成受击或 K.O.，第二个已有效且触及身体的打击仍按快照结算，双方反制伤害一致；打击仍优先压投。

肢体型有效攻击框互相交叠、侧移深度一致、双方无无敌，并且双方都未触及对方身体，才进入拼招。显示双色火花和 `CLASH · 拼招`，停顿 0.075 秒，随后双方 10F 固定恢复并轻后退。保留撞拳姿态、清理后续输入，但不保留攻击框，不扣生命，也不获得命中确认或付费取消。近距离双方拳都碰身体时继续相打。

## 精确防御与回波

本文 F 为 60Hz 设计帧；模拟仍以 120Hz 固定步长运行。

精防要求地面可防状态、无硬直，新按与当前对手位置相对的后方向。窗口 3F、再次开启间隔 20F；放开后方向或暂停/打开说明等清输入时立即失效，hitstop 不消耗窗口。仍须站防跳入、下后防低段，攻击/空中/投技不获精防。成功时不削血、不耗防御条，6F 防御硬直、较小推力，获得 4 潮能并显示双色光环。旧直接防御按钮和提前一直按后只产生普通防御。

轻+重的中段防反起手 4F 内遇到潮波，会把它返还；超过 4F 但在原 0.225 秒反击窗口内仍可化解。每颗波最多反弹一次，再次遇到正确防反会消失。回波保留 `sourceCharacter`、`sourceSide`、招式、源威力、速度和剩余寿命，更新当前归属、方向与 `reflections`；真正打回原发波者，不能确认新归属者正在使用的无关招式。精防只挡波，普通拳脚不返还。

## 空中角色技修复

旧实现一按空中角色技就强制下降，正常跳跃约 200ms 后出招可能在起手完成前落地，从未出现有效帧。现在起手保留原跳跃惯性，第一次跨过有效期边界再开始俯冲；水平突进保持即时反馈。地面接触仍终止空中攻击并按命中/防御/落空进入对应落地恢复，不能把落地后的攻击框留下。

## 验证入口

`pnpm run duel:test` 覆盖轮廓来源与复杂度、镜像与衣装一致性、相打/双 K.O.、拼招恢复/取消限制、精防高度/方向/时窗、回波归属/寿命/再次化解、二维对波、蹲躲与低空接触以及俯冲起手。`pnpm run duel:simulate` 执行 600 场 CPU 比赛，检查卡局和资源范围。

`pnpm run duel:verify:contact` 仅用真实键盘与公开文本状态，验证三人自然拼招、近距离相打、两侧精防和返波后真实伤害。训练模式显示绿受击、红攻击、黄推挤的分段框；公开状态报告同一 pose。脚本用安装版静音 Chrome、全页面截图、像素/DOM/canvas 检查与错误记录；`TIDAL_DUEL_PUBLIC_MATCH=1` 验证生产环境没有可变开发钩子。截图仍须打开目检，具体证据见 [QA](tidal-duel-qa.md)。

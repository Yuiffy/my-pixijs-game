## 本轮重建方法

`scripts/prepare-liuzhou-eshan.py` 离线读取 `city-map.json`，调用项目原有地形三角面采样器，沿源路径建立 3.2～4 米估算通道。源节点在平面上不移动；先对纵断面进行图平滑与坡度约束，再对实际网格三角面约束坡度，避免折弯处最近线段切换生成陡小面。道路宽度、连续坡面、铺石纹理和局部修坡均为游戏重建，不是测量得到的真实石阶。

仅将窄通道从既有地形中裁出，补齐与原始地形之间的边坡竖面；地形绘制、Rapier、贴地表面、人物高度、镜头和存档查询共用最终三角面。数值修整量记录在 `eshan-layout.json`，包括 `maxNodeDemAdjustment`、`maxSurfaceGrade`、`maxMeshCorrection` 和 `maxSurfaceDemAdjustment`。不能把更密的网格当成新增的高程测量。

本轮最终网格的最大源高程偏移约 11.14 米，最大三角面坡度约 0.775；入口连接端另锚定到原始地形，避免生成通行台坎。这些数值说明本轮仍是为连续通行进行的局部重建，不能据此声称实地高差精度达到米级。部分挡土竖面较高、边坡仍生硬，真实岩阶、缓坡过渡和设施外观需要继续核查细化。

封边修正：旧挡土面按约0.8米等距采样，跨越步道网格边和山坡单元对角线时，边缘最高有约0.104米/0.092米误差，并存在155段物理四边形交叉。现在从实际步道三角面边界提取封边，在既有地形单元边、对角线以及挖填高差过零处切分；可见顶部另与铺石的0.015米绘制偏移对齐，底部与地形的-0.12米绘制偏移对齐，避免绘制层留下0.135米缝隙。物理高程仍用原三角面。`wallSealing`记录方法与偏移；原边界、路径、节点、路面顶点/三角面、山体裁切和原DEM均不改变。这只是修复重建网格的接缝，不是新增测量或恢复真实挡土墙外观。

陡峭侧路 `1071650440` 保留源路径与原始地形，不套用平缓步道修整；没有精确岩阶和攀爬结构资料，尚未完成这条侧路的普通步行还原。沿该线现有粗高程还有数十米局部起伏，不能简单铺一组台阶并称其还原。可用已有飞行巡览查看，不声称所有登山支路均已走通。

入口石墙与指示牌、长椅、树林、扶手和两位居民均为估算布置；居民在通道旁停留，不是实际人物。原来处于山侧、没有接入步道的悬空公园标牌已移至源东侧入口连接附近。树木避开全部源步道和两处小建筑轮廓。

## 重建与验证

离线工具依赖 Python Shapely >= 2.1、NumPy、SciPy，以及项目已有 Node/TypeScript，不需要网络或测绘账号。

```powershell
python scripts/prepare-liuzhou-eshan.py
python scripts/prepare-liuzhou-eshan-edges.py
python scripts/tests/liuzhou-eshan-seams.py
node --test scripts/tests/liuzhou-eshan.test.mjs
node scripts/verify-liuzhou-eshan.cjs
```

浏览器测试使用独立静音安装 Chrome，在创建页面之前模拟 Pointer Lock；普通输入从老街飞到东侧入口，落地后徒步上山、返回及进入下部园路，检查休憩棚、旅客交谈、山上存档刷新和手机画面。运行报告和截图只证明实际覆盖的路线，不代表精细现实地形、全部侧路或完整城市已完成。

完整生成器已接入相同封边工具；只需修复既有网格接缝时，可单独运行`prepare-liuzhou-eshan-edges.py`，无需重新求解纵断面。独立接缝检查从相邻三角面计算高度，验证整个边界闭合、物理及可见四边形不自交。
